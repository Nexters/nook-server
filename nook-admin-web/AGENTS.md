# Nook Admin Web Guide

이 문서는 `nook-admin-web` 하위의 화면, 컴포넌트, 스타일 작업에 적용한다.
상위 저장소의 `AGENTS.md`와 함께 따르며, 명시적인 사용자 요구가 우선한다.

## Product Principle

어드민은 시스템 구조를 설명하는 화면이 아니라 운영자가 상태를 파악하고 다음 행동을 안전하게 수행하는 도구다.

- 화면에 정보를 추가하기 전에 운영자의 판단 또는 행동에 필요한지 확인한다.
- 인증 provider, 프록시, 배포 환경 등 구현 세부사항은 문제 해결에 직접 필요하지 않으면 노출하지 않는다.
- 이메일과 같은 운영자 식별 정보는 감사나 책임 확인이 필요한 위치에서만 표시한다.
- 기술 용어보다 운영자가 이해하는 업무 용어를 사용한다.

## Navigation

- 다른 관리 대상이 목록, 카드, 관계 정보로 노출되면 해당 대상의 관리 상세로 이동할 수 있어야 한다.
- 같은 어드민 내부 이동은 현재 탭에서 수행하고, 원문과 외부 provider 링크만 새 탭으로 연다.
- 반복되는 목록 아이템은 제목뿐 아니라 아이템의 주요 영역 전체를 클릭할 수 있게 한다.
- 아이템 전체 이동과 수정, 삭제, 외부 링크 같은 보조 행동을 같은 클릭 영역에 중첩하지 않는다.
- 링크와 버튼은 시각적 표현뿐 아니라 키보드 포커스와 접근 가능한 이름을 제공한다.
- 사용자가 상세에서 목록으로 돌아갈 때 기존 필터, 정렬, 페이지 문맥을 가능한 한 보존한다.

## Information Hierarchy

- 화면 제목 아래에는 그 화면의 목적 또는 현재 대상의 핵심 상태만 둔다.
- 가장 중요한 식별 정보, 상태, 영향 범위, 주 행동 순서로 배치한다.
- 내부 ID, provider ID, request ID는 보조 정보로 표현하고 영문·식별자 서체를 사용한다.
- 상태는 색상만으로 구분하지 않고 항상 텍스트를 함께 표시한다.
- 동일한 상태와 동작에는 모든 화면에서 같은 이름, 색상, 컴포넌트를 사용한다.
- 데이터가 없는 상태와 로딩 중인 상태, 조회 실패 상태를 서로 구분한다.

## Actions And Safety

- 화면별 주 행동은 하나를 우선하고 나머지는 보조 행동으로 표현한다.
- 수정, 교정, 재처리 같은 행동은 대상과 영향 범위를 행동 전에 보여준다.
- 삭제나 되돌리기 어려운 변경은 명시적인 확인 단계와 결과 안내를 제공한다.
- 제출 중에는 중복 실행을 막고 성공과 실패 결과를 사용자가 확인할 수 있게 한다.
- 사용자가 입력한 검색어와 수정 내용은 실패 후에도 가능한 한 유지한다.

## Lists And Filters

- 기본 정렬은 운영자가 가장 먼저 확인할 가능성이 높은 항목을 우선한다.
- 검색 필드의 라벨은 검색 가능한 속성을 구체적으로 설명한다.
- 행을 클릭할 수 있다면 hover, focus, cursor로 상호작용 가능성을 드러낸다.
- 테이블에는 비교와 판단에 필요한 필드만 두고 상세 정보는 상세 화면으로 보낸다.
- 필터와 페이지네이션 변경 후에도 현재 업무 문맥을 유지한다.

## Visual And Responsive Behavior

- `src/main.tsx`의 MUI theme와 `src/styles.css`의 Nook 토큰을 우선 재사용한다.
- 임의의 색상, 폰트, 그림자, 라운딩을 화면마다 새로 만들지 않는다.
- 데스크톱에서는 정보 비교 효율을 우선하고, 좁은 화면에서는 행동과 핵심 정보가 가려지지 않게 한다.
- hover에만 의존하는 정보나 행동을 만들지 않는다.

## Verification

- 변경한 흐름의 시작 화면부터 목적 화면까지 실제 Chrome에서 확인한다.
- 내부 이동, 외부 링크, 필터, 페이지네이션, 주요 수정 다이얼로그의 기존 동작을 회귀 확인한다.
- `pnpm build`와 저장소 루트의 `./gradlew check`를 실행한다.
- 콘솔 오류, 잘린 텍스트, 클릭 영역 중첩, 빈 상태 오인을 확인한다.
