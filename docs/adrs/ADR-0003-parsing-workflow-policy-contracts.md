# ADR-0003 파싱 워크플로와 정책 공통 계약

- 상태: 승인
- 일자: 2026-08-23

## 배경

파싱 실행 규칙과 관리자 파싱 과정의 설명이 별도 코드로 관리되어, 실행 로직이 변경될 때 운영자
화면의 조건과 순서가 뒤처질 수 있다. 소스 코드 분석이나 문자열 복제로 화면을 생성하면 실행과
설명의 일치를 보장하기 어렵다.

## 결정

`nook-api-application`의 processing 패키지에 워크플로, 단계, 규칙, 판정 결과와 카탈로그의 공통
계약을 둔다. 실행 가능한 규칙은 표시용 정의와 evaluator를 함께 소유하고, 평가 결과에는 정의의
고정 `ruleId`를 자동으로 포함한다. 관리자 어댑터는 같은 카탈로그를 조회해 화면용 DTO로 변환한다.

워크플로와 규칙은 프레임워크 타입에 의존하지 않는다. Provider 호출, 트랜잭션, 재시도와 progress
갱신은 기존 유스케이스가 계속 담당한다. 텍스트 단서 검증, 후보 판정, 이미지 분석 여부와 제목
결정은 영역별 정책으로 이전하되 범용 workflow runner는 도입하지 않는다.

## 결과

- 실행 규칙과 관리자 설명이 같은 정의와 임계값을 사용할 수 있다.
- 고정 ID로 규칙 정의와 실행 trace를 연결할 수 있다.
- 실제 trace는 `ruleId`, 판정 outcome, reason과 입력 facts를 저장한다.
- 어드민의 대상 판정 노드는 실행과 같은 카탈로그에서 조건과 임계값을 조회한다.
- 카탈로그 생성 시 ID 중복과 잘못된 단계 참조를 조기에 발견한다.
- provider 호출과 영속화 orchestration은 기존 유스케이스에 유지한다.
- 정책 버전 및 과거 규칙 스냅샷은 이번 결정에 포함하지 않는다.
