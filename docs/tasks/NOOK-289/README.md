# NOOK-289 파싱 누락 진단 및 명시적 검색어 후보 복구

## 목적

원문의 번호 장소 목록과 추출 결과를 대조해 모델이 장소 단서 자체를 누락한 경우도 최종 진단에
포함한다. 검색어에 후보의 전체 상호명이 명시된 안전한 경우에는 모델 선택 실패로 남기지 않고
결정적으로 복구한다.

## 범위

- 1부터 시작하는 연속 번호 목록의 예상 장소 수 계산
- 번호 목록 항목과 추출 단서의 일대일 커버리지 판정
- `NOT_EXTRACTED`, `RESOLUTION_FAILED` 실패 유형 기록
- 1위 후보의 전체 상호명이 검색어에 명시되고 후보가 하나인 경우 자동 확정
- 장소 단서명과 실제 검색어를 규칙 trace에 기록
- 어드민 정책 카탈로그와 파이프라인에 원문 커버리지 단계 노출
- 어드민 게시글 및 실행 요약에서 실패 유형 구분
- 게시글 402 형태의 중복 username 및 복수 실패 회귀 테스트

## 제외 범위

- 정책 버전 저장
- DB 스키마 및 DDL 변경
- 기존 endpoint, 요청 필드, 상태 코드 변경
- 일반적인 검색 1위 후보 자동 선택
- 이미지·동영상 thumbnail URL의 OCR 입력 사용

## 성공 기준 및 검증

- 12개 번호 항목 중 11개 단서만 추출되면 예상 장소 수 12와 미추출 항목 1개가 기록된다.
- 같은 username을 공유하는 서로 다른 장소가 하나의 단서로 중복 충족되지 않는다.
- 단서 미추출과 후보 선택 실패가 같은 실행에 함께 저장되고 어드민에 모두 표시된다.
- `바버샵 서촌`의 유일한 1위 `바버샵` 후보는 복구되며 복수 일치 후보는 자동 선택하지 않는다.
- 과거 진단 JSON의 누락된 `type`은 `RESOLUTION_FAILED`로 호환된다.
- `./gradlew detekt`, `./gradlew test`, `./gradlew check`, 어드민 `pnpm build`가 통과한다.

## 배포 및 롤백

스키마 변경 없이 애플리케이션과 어드민을 함께 배포한다. 롤백 시 이전 애플리케이션은 새 진단 JSON의
추가 필드를 무시할 수 있으며, 문제가 있으면 이전 버전으로 되돌린다.
