# 어드민 장소·게시물 저장 회원 ID와 이름 표시

## 목적

어드민 운영자가 장소와 게시물을 저장한 회원을 회원 ID와 닉네임으로 확인한다. 어드민에서는 원문 인스타그램 작성자 대신 저장 회원 정보를 표시한다.

## 범위

- 장소 상세와 게시물 상세에 현재 저장 중인 회원의 ID와 닉네임을 표시한다.
- 게시물 상세의 인스타그램 작성자 표시와 수정창의 작성자 입력을 제거한다.
- 수정 요청은 기존 `authorIdentifier` 값을 보존하여 기존 API와 데이터에 영향을 주지 않는다.
- 장소 상세의 연결 게시글에도 게시글별 저장 회원 닉네임과 ID를 표시한다.
- 처리 상태 목록·상세와 기존 복구 상세에 저장 회원 정보를 표시한다.
- 연결 게시글과 처리 상태 목록은 저장 회원을 게시글별로 일괄 조회한다.
- 게시글 관리 목록은 인스타그램 작성자 대신 현재 저장 회원의 닉네임과 ID를 표시한다.
- 저장 회원이 여러 명이면 모두 표시하고, 없으면 `없음`으로 표시한다.
- 현재 목록 페이지의 저장 회원을 일괄 조회하고 회원 수와 목록을 같은 조회 결과로 계산한다.
- 저장 회원 수와 목록은 삭제되지 않은 저장 데이터 기준으로 일치시킨다.

## 제외 범위

- 저장 회원 목록 검색, 정렬, 페이지네이션
- 앱의 저장 동작 및 공개 API 변경
- 데이터베이스 스키마 변경

## 검증

- `./gradlew check`
- `pnpm build` (`nook-admin-web`)
- 어드민 게시물·장소·처리 상세의 저장 회원 표시와 작성자 표시·입력 제거를 Chrome에서 확인

## 목록 표시 후속 변경 검증 결과

- 저장 회원 조회·페이지별 그룹화·회원 수·삭제 저장 제외 테스트 3개 통과.
- `./gradlew detekt` 통과.
- `pnpm build` 통과.
- Chrome에서 검증용 API 데이터로 회원 1명·여러 명·없음, 검색, 페이지 이동, 상세 진입과 콘솔 오류 없음을 확인.
- `./gradlew check`는 기존 `ParsingSummaryMySqlTest`의
  `legacy fingerprint migrates without republishing an existing failure` 1건 실패로 전체 통과하지 못함.
  변경 없는 `origin/main` 소스를 별도 디렉터리에서 실행해 동일 실패를 재현함.
- 로컬 검증 실행 시 Gradle 힙 2GB, Docker Desktop 연결 주소와 컨테이너 내부 소켓 경로를 지정함.

## 전체 화면 후속 변경 검증 결과

- 게시글 저장 회원 조회 3개, 장소 연결 게시글 1개, 처리 상태 MySQL 테스트 6개 통과.
- `./gradlew check`의 정적 분석·모듈 의존 검사와 나머지 모듈 테스트 통과.
  infrastructure 테스트 378개 중 기존 `ParsingSummaryMySqlTest` 실패 1건으로 전체 check는 실패.
- `pnpm build` 통과.
- Chrome의 로컬 검증 API로 장소 연결 게시글의 회원 1명·여러 명·없음,
  연결 게시글 상세 이동, 작성자 표시·입력 제거, 처리 목록·상세 회원 표시를 확인.
- 수정 저장 요청의 `authorIdentifier`가 상세 응답의 기존 값과 동일함을 확인.
- 브라우저 콘솔 오류 없음.
- 기존 게시글 관리 목록 수정은 develop에 반영하고 개발 API·워커·어드민 배포 완료.
  개발 어드민에서 실제 회원 닉네임·ID 표시와 API·워커 헬스체크 정상 확인.
- 이 전체 화면 후속 변경은 PR 리뷰 전 로컬 검증 상태이며 아직 배포하지 않음.
