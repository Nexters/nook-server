# NOOK-276 게시물 제목 OCR 통합·검증 및 어드민 재생성

## 목적

첫 이미지를 별도 OpenAI Vision 요청으로 해석해 설명문, 문자열 `null`, 중복 문구가 제목으로
저장되는 문제를 해결한다. 공용 OCR 전사를 제목과 장소 파싱이 재사용하고, 운영자가 어드민에서
개별 게시물 제목만 안전하게 재생성할 수 있게 한다.

## 범위

- 첫 이미지 OCR을 `ocr.image-text.provider-chain` 기반 공용 OCR로 수행한다.
- 콘텐츠 제목 파싱과 장소 파싱이 첫 이미지 transcript를 재사용한다.
- 장소 OCR은 캐시에 없는 이미지만 추가 전사해 기존 transcript와 병합한다.
- 제목 선택 모델은 OCR 결과에 실제 존재하는 문구 또는 `null`만 반환할 수 있다.
- 문자열 null, 설명문, 기본 문구를 제목 후보에서 제거한다.
- 본문의 명시적 컬렉션 제목, 검증된 표지 제목, 검증된 본문 AI 제목 순으로 선택하고
  유효한 후보가 없으면 `null`을 저장한다.
- 어드민 게시물 목록과 상세에 제목 재생성 버튼을 추가한다.
- 제목 재생성은 제목만 변경하며 변경 전후 값과 운영자 사유를 감사 로그에 남긴다.
- 관련 HTTP Client 요청과 회귀 테스트를 추가한다.

## 제외 범위

- 게시물 본문, 미디어 또는 장소 매핑 전체 재파싱
- 기존 운영 데이터 일괄 재생성
- OCR bounding box 공통 모델 도입
- 공개 API 계약 변경
- DB 스키마 변경

## 성공 기준

- 첫 이미지 OCR이 런타임 provider chain을 따르고 제목과 장소 파싱에서 중복 호출되지 않는다.
- 장소 이미지 분석 시 기존 transcript에 없는 이미지만 OCR한다.
- `null null`, 이미지 설명문, 중복 문구, `Instagram 게시물`, `방문해보기 좋은 곳`이
  제목으로 저장되지 않는다.
- OCR에 없는 문구를 표지 제목으로 선택할 수 없다.
- 어드민 목록과 상세에서 제목을 재생성할 수 있고 실패하면 기존 제목을 유지한다.
- 외부 provider 호출은 DB 트랜잭션 밖에서 실행한다.
- `nook-admin-web`의 `pnpm build`와 루트의 `./gradlew check`가 성공한다.

- `./gradlew check` 성공
- `nook-admin-web`의 `pnpm build` 성공
