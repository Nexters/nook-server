# NOOK-383 지도·검색 장소의 공유 상세 접근 정보

## 목적

지도 핀이나 저장 장소 검색 결과에서 공유 장소를 선택할 때, 최근 저장 공간과 동일하게
공유 아카이브의 연결 게시물과 게시물에 포함된 장소를 조회할 수 있도록 상세 접근 정보를 제공한다.

## 범위

- `GET /api/v1/places/map`의 각 장소에 `accessType`, `shareToken` 추가
- `GET /api/v1/places/saved/search`의 `items`에 같은 필드 추가
- 최근 저장 공간의 공유 토큰 조회 SQL을 공통으로 사용
- OpenAPI 스키마, HTTP Client 예제, 응답·영속성·H2 쿼리 테스트 갱신

## 응답 및 프론트 연동

| accessType | shareToken | 상세 조회 |
| --- | --- | --- |
| OWNED | null | `GET /api/v1/places/{placeId}` |
| SHARED | 활성 공유 토큰 | `GET /api/public/v1/groups/{shareToken}/places/{placeId}` |

내 활성 저장 게시물로 접근할 수 있으면 OWNED를 우선한다. 공유 구독으로만 접근 가능한 장소는
SHARED와 토큰을 반환한다. 공유 링크의 만료·해제, 아카이브·게시물·연결 삭제를 반영하고,
여러 구독이 있으면 구독 생성 시각과 ID의 내림차순으로 하나를 선택한다.
지도 아카이브 필터가 있으면 선택한 공유 아카이브 안에서 토큰을 선택한다.
검색은 기존과 동일하게 groupId 미지정 시 공유 장소를 포함하며, groupId 지정 시 내 아카이브만 검색한다.

기존 응답에 필드만 추가하며 장소 목록·건수·정렬·페이지네이션 계약은 유지한다.
프론트는 지도 및 검색 응답의 SHARED 항목을 공유 상세 API로 연결해야 한다.

## 제외 범위

- 지도 핀·플로팅 카드 등 프론트 UI 구현
- 기존 내 장소 상세 API의 게시물 조회 범위 변경
- 내 장소와 공유 장소가 겹칠 때 공유 게시물까지 합쳐 반환하는 동작
- 검색 조건·알고리즘·아카이브 필터 정책 변경
- 스키마 변경, DDL, 배포

## 성공 기준 및 검증

- 지도·검색 응답에서 OWNED/null 및 SHARED/토큰이 전달된다.
- 공유 토큰은 접근 가능한 구독에서 결정적으로 선택되고 지도 아카이브 필터를 따른다.
- 해제·만료된 링크는 토큰 선택에서 제외되며 접근권이 모두 사라지면 장소도 제외된다.
- 기존 필터·건수·정렬·페이지네이션 및 최근 저장 토큰 정책을 유지한다.
- 단위 테스트, H2 쿼리 테스트, Detekt, 모듈 의존 검사로 검증한다.
- Docker/MySQL 컨테이너 테스트와 실제 프론트 탐색은 실행하지 않는다.

### 검증 결과 (2026-11-20)

- 관련 테스트 38개 통과: H2 쿼리 11개, 지도 어댑터 8개, 검색 어댑터 2개, 장소 컨트롤러 17개
- Docker/MySQL 테스트 7개 클래스를 제외한 `check` 통과 (Detekt, 테스트, 모듈 의존 검사)
- 임시 Gradle init script에서 `Test.exclude("**/*MySqlTest*")`를 적용한다.
  저장소의 테스트 설정은 변경하지 않으며 MySQL 컨테이너 테스트 7개 클래스는 실행하지 않는다.
- 실제 MySQL SQL 실행, 외부 provider 호출, 프론트 화면 확인 및 배포는 수행하지 않는다.

실행 명령:

```sh
./gradlew -Dorg.gradle.jvmargs='-Xmx2g -XX:MaxMetaspaceSize=768m' \
  --max-workers=2 -I /tmp/nook-383-no-containers.gradle check
```

## 실제 환경 연동 확인 절차

1. 유효한 공유 아카이브를 구독한 사용자로 지도와 저장 장소 검색을 호출한다.
2. 공유로만 접근 가능한 장소에 `accessType: SHARED`와 `shareToken`이 있는지 확인한다.
3. 해당 토큰과 장소 ID로 공유 장소 상세 API를 호출해 최근 저장 공간과 동일한 연결 게시물을 확인한다.
4. 프론트에 API 분기를 반영한 뒤 지도 핀·검색 카드에서도 같은 상세가 표시되는지 확인한다.
5. 공유 링크를 해제하거나 만료시키면 장소가 지도·검색에서 제외되는지 확인한다.

실제 API 호출과 화면 검증은 이 작업의 자동 검증에 포함하지 않는다.
