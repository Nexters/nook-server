# NOOK-415 게시물 재처리 콘텐츠 교체 오류 수정

이슈: https://linear.app/nooknook/issue/NOOK-415

## 목적과 성공 기준

개발 환경 저장 게시물 499(원본 423)은 재시도 요청이 수락되고 캐시 수집·장소 추론까지
성공했지만, 기존 미디어 교체 중 `post_media.idx_u_post_id_display_order` 중복 키 오류로 실패했다.
기존 이미지 순번과 해시태그를 재사용하는 반복 재처리가 성공하고, 후속 저장 실패 시 기존
본문·미디어·해시태그·처리 상태가 모두 복구되는 것을 성공 기준으로 삼는다.

## 변경 범위

- 콘텐츠 완료 저장 트랜잭션에서 미디어·해시태그 삭제를 flush한 뒤 새 행을 저장한다.
- 파생 삭제 쿼리가 예약한 DELETE보다 IDENTITY INSERT가 먼저 실행되는 순서를 바로잡는다.
  두 저장소는 같은 영속성 컨텍스트를 사용하므로 한 번의 flush로 두 삭제를 반영한다.
- 기존 짧은 트랜잭션과 수동 본문 보호, 오래된 실행 차단 정책을 유지한다.
- 외부 호출, API 계약과 DB 스키마 변경은 없다. DDL은 필요하지 않다.

## 검증

- 실제 JPA 저장소와 H2로 같은 이미지 순번·겹치는 해시태그의 반복 교체를 검증한다.
- 다른 게시물의 기존 데이터와 관리자가 수동 수정한 콘텐츠가 보존되는지 검증한다.
- 후속 작업 저장 실패를 주입해 이미 flush한 삭제·신규 저장·완료 상태가 함께 롤백되는지 검증한다.
- 수정 전 H2 테스트에서 같은 미디어 유니크 제약 위반을 재현했다.
- H2의 스키마 전체 인덱스 이름 제약을 맞추기 위해 테스트에서만 테이블명을 접두사로 붙인다.
  실제 칼럼과 유니크 제약은 유지하며 운영 엔티티 정의는 바꾸지 않는다.

개인 검증 지침에 따라 단위·H2, Detekt, 모듈 의존 검사를 실행하며 MySQL 컨테이너 테스트는
임시 Gradle init script에서만 제외한다. Docker·브라우저·실제 provider 호출은 수행하지 않는다.

### 검증 결과 (2026-10-23 KST)

- 신규 H2 회귀 3개 포함 단위·H2 테스트 952개 통과, 실패·오류·skip 0.
- Detekt, 모듈 의존 방향 검사, `git diff --check` 통과.
- MySQL 컨테이너 테스트 7개 클래스(`**/*MySqlTest*`)를 제외한 check 통과.
  MySQL 검증까지 포함한 전체 check를 통과한 것은 아니다.

```bash
./gradlew check --continue --init-script /tmp/nook-415-unit-h2.gradle --no-daemon \
  --max-workers=2 -Dorg.gradle.jvmargs='-Xmx2g -XX:MaxMetaspaceSize=768m'
```

임시 init script는 모든 Test 태스크에서 `**/*MySqlTest*`만 제외한다.

## 제외 범위와 배포 후 확인

저장 게시물 498의 원문 접근 불가, 일부 개발 origin의 CORS 403, 인증 실패는 별도 원인이다.
이번 변경은 콘텐츠 저장 단계의 중복 키 오류를 해결한다.

실제 DB 수정·재시도·배포와 이슈 완료 처리는 포함하지 않는다.
워커 배포 후 개발 계정에서 게시물 499 재시도를 요청하고 콘텐츠 완료, 장소 처리 진행과
중복 키 오류 미발생을 확인해야 한다. 외부 원문의 상태에 따른 수집 성공 자체는 미검증이다.
롤백은 해당 코드 변경을 되돌리며 데이터 마이그레이션은 필요하지 않다.
