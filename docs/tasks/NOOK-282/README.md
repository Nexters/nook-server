# NOOK-282 장소 후보 중복 및 태그 상호 접두어 판정 보완

## 목적

장소 검색에는 성공했지만 provider 간 동일 후보가 중복되거나 태그 프로필 상호의 업종 접두어가
지도 상호와 달라 최종 장소 판정에서 탈락하는 문제를 해결한다.

## 원인

- 네이버와 카카오가 같은 상호와 주소를 반환해도 provider 식별자가 달라 별도 grounded 후보로 남는다.
- 태그 프로필 `카페흐릇`과 지도 상호 `흐릇`처럼 업종 접두어만 다른 경우 정확한 후보가 검색돼도
  짧은 상호 부분 일치 보호 규칙에 의해 grounding이 거부된다.

## 범위

- 주소 힌트 유무와 관계없이 최종 판정 전에 동일 상호·주소 후보를 논리적으로 병합한다.
- 병합한 후보의 검색어 근거를 합쳐 보존한다.
- 태그 프로필과 기존 이미지 단서가 하나로 일치한 경우에만 알려진 업종 접두어를 제거한 별칭을 추가한다.
- 별칭은 두 글자 이상일 때만 허용한다.
- 실제 송정·흐릇 실패 흐름을 최종 장소 확정까지 검증하는 회귀 테스트를 추가한다.

## 제외 범위

- 특정 상호명 또는 주소 하드코딩
- 장소 검색 결과 수 확대
- 태그된 프로필을 독립 장소로 추가
- DB 스키마 변경과 기존 게시물 일괄 재파싱

## 성공 기준

- 네이버·카카오가 반환한 동일 송정 후보가 하나의 grounded 후보로 확정된다.
- 태그 프로필로 교정된 `카페흐릇` 단서가 지도 상호 `흐릇`과 연결된다.
- 서로 다른 상호 또는 주소의 후보는 병합하지 않는다.
- 기존 모호 후보 및 OCR grounding 보호 테스트가 유지된다.
- `./gradlew check`가 통과한다.
