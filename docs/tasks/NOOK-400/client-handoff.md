# 클라이언트 전달 문안 — NOOK-400

온보딩 Instagram CTA 이후 첫 저장 전환 추적을 위한 서버 계약입니다.
서버/DDL 배포 완료 후 연동해 주세요. 같은 내용을 NOOK-400 Linear 코멘트로 전달합니다.

## 요청

`POST /api/v1/onboarding/events`

```http
Authorization: Bearer <NOOK access token>
Content-Type: application/json
```

```json
{
  "eventId": "60d86756-c4cd-4e67-bcca-c6b08cecd4a4",
  "eventName": "INSTAGRAM_CTA_CLICK",
  "occurredAt": "2026-10-07T14:00:00Z"
}
```

- 온보딩 Instagram CTA를 탭한 순간 UUID와 실제 발생 시각을 만들어 로컬에 보관해 주세요.
  네트워크 응답을 기다리느라 Instagram 이동을 막지 않아야 합니다.
- 실제 탭마다 새 ID를 생성하고 재전송은 같은 ID/종류/시각을 유지해 주세요.
  서버는 사용자별 최초 CTA를 집계 기준으로 삼지만 수집은 각 실제 탭을 기록합니다.
- `occurredAt`은 UTC ISO-8601이며 서버 현재 시각 이하, 과거 7일 이내여야 합니다.
  시계 오차로 400이 발생할 수 있으므로 단말 시간/서버 시간 차이 처리 방안을 확인해 주세요.
  재시도 때문에 발생 시각을 현재로 덮어쓰면 안 됩니다.
- 사용자 ID는 보내지 않습니다. 인증 정보로 서버가 식별합니다.
  로컬 큐는 발생 당시 계정에 귀속하고, 계정 변경 시 다른 계정 토큰으로 보내지 마세요.
- `204`(본문 없음)는 수집 성공 또는 이미 수집한 같은 이벤트입니다. 큐에서 제거해 주세요.
- 네트워크 오류/5xx는 지수 backoff로 재시도해 주세요. 401은 같은 사용자 토큰 갱신 후 재시도합니다.
  400은 잘못된 종류/UUID/시각 또는 동일 ID의 다른 내용이므로 무한 재시도하지 말고 진단해 주세요.
  보관/재시도 기간은 발생 후 7일 이내입니다.
- 저장 완료 이벤트는 서버에서 기록합니다. 클라이언트에서 별도 전송할 필요가 없습니다.
  여기서 저장 성공은 보관함 저장이며 파싱 완료와 구별합니다.

## Share Extension 확인 요청

아래는 이 저장소에서 확인할 수 없어 답변이 필요합니다. 기본 CTA 연동은 답변과 병행할 수 있습니다.

1. 온보딩 CTA는 로그인 이후에만 노출되는지, 다시 노출될 수 있는지 확인 부탁드립니다.
2. NOOK Share Extension이 실제 실행된 시점에 이벤트를 수집할 수 있나요?
3. 앱 본체와 같은 NOOK 계정으로 인증된 요청을 보낼 수 있나요? 토큰 만료 시 갱신도 가능한가요?
4. 취소/종료/오프라인 상황에도 로컬 큐에 남기고 이후 같은 계정으로 재전송할 수 있나요?
5. 다른 앱에서 열린 Share Extension도 포함되는지, Instagram에서 열렸다고 확실히 식별할 수 있는지 알려 주세요.
   서버는 이 이벤트만으로 Instagram 출처를 단정하지 않습니다.
6. 적용 가능한 앱 버전과 일정, 테스트 담당자를 공유 부탁드립니다.

가능하면 같은 API에 `eventName: "SHARE_EXTENSION_OPEN"`으로 보내 주세요.
진입 이벤트는 실제 실행마다 한 번이며 화면 재렌더링마다 보내면 안 됩니다.
기존 CTA ID를 재사용하지 말고 실행 이벤트의 독립적인 UUID를 만듭니다.

## 공동 검증

- CTA 탭 즉시 앱 전환해도 기록 보존, 오프라인 후 복귀 재전송, 중복 요청 1건
- 로그아웃/계정 전환 시 원래 계정 이벤트가 다른 계정으로 전송되지 않음
- CTA → 신규 게시물 저장 시 5/10/30분 지표에 1명 반영
- 이미 저장된 게시물 재요청은 신규 저장 이벤트로 기록되지 않음
- Share Extension 지원 시 실행 → 취소 / 실행 → 저장을 각각 확인
