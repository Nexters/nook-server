# NOOK-275 장소 사진 Naver 검색 fallback 개선 및 성능 검토

## 목적

Google Maps 장소 결과에 사진이 없을 때 Naver 장소 검색 성공률을 높이되, 동명이점이나 인접 장소를
잘못 선택하지 않는다. 여러 장소의 사진 수집 방식은 실제 운영 시간과 actor 호출 비용을 함께 고려한다.

## 범위

- Naver 장소 검색 actor에 장소별 검색어 두 개를 한 번에 전달한다.
  - `장소명 + 도로명 + 건물번호`
  - `장소명 + 구/군`
- 도로명 검색 결과를 구/군 검색 결과보다 우선한다.
- 최종 후보는 다음 조건을 모두 만족해야 한다.
  - 장소명 일치
  - 도로명과 건물번호 일치
  - 기준 좌표로부터 300m 이내
- 장소별 provider 체인을 최대 6개까지 병렬 실행한다.
- 각 장소가 사진을 확보하면 다른 장소의 fallback 완료를 기다리지 않고 즉시 완료 처리한다.
- 반환 목록은 병렬 완료 순서와 관계없이 기존 요청 순서를 유지한다.

## 성능 판단

2026-08-22 dev VM에서 동일한 장소와 Apify 계정으로 직접 측정한 결과는 다음과 같다.

| 구간 | 방식 | 소요 시간 | Apify 비용 |
| --- | --- | ---: | ---: |
| Google Maps 6곳 | 배치 1회 | 35.7초 | $0.0502 |
| Google Maps 6곳 | 장소별 6병렬 | 14.2초 | $0.0512 |
| Naver 검색 2곳 | 배치 1회 | 28.6초 | $0.00755 |
| Naver 검색 2곳 | 장소별 2병렬 | 14.2초 | $0.00760 |

Google은 약 60%, Naver 검색은 약 50% 빨라졌으며 실제 비용 차이는 각각 약 2%, 1% 미만이었다.
장소별 체인을 최대 6개 병렬 실행하는 방식을 선택한다. Naver 사진 actor는 배치 및 개별 호출 모두 반환이
불안정했으므로, 검색 응답의 대표 `Images`를 우선 저장하고 부족한 사진만 상세 actor 결과로 보충하는 기존
동작을 유지한다.

## 제외 범위

- nook-client 변경
- 장소명 단독 검색
- 6개를 초과하는 actor 병렬 실행
- 공개 API 계약 변경
