# NOOK-287 장소 부분 성공 가시화 및 검색 근거 기반 후보 복구

## 목적

장소 파싱이 일부 장소만 해결한 경우 관리자에서 완전 성공처럼 보이는 문제를 수정하고, 실제 지도
후보가 존재하지만 지역·표기 차이로 누락되는 장소를 안전하게 복구한다.

## 재현 사례

- live post 517은 본문에서 4곳을 소개하지만 텍스트 장소 단서가 비어 장소 파싱이 실패했다.
- live post 520은 7곳을 추출하고 4곳만 해결했지만 관리자에서는 `COMPLETED`로 표시된다.
- live post 521은 6곳을 추출하고 3곳만 해결했지만 관리자에서는 `COMPLETED`로 표시된다.

## 범위

- 관리자 게시물 목록과 상세에 `PARTIAL`, 추출·해결·미해결 수와 미해결 사유를 노출한다.
- provider 후보의 검색어 근거를 사용해 유일한 장소 후보를 복구한다.
- 생활권 지역명이 도로명 주소에 없더라도 복수 검색 근거가 일치하면 별도 안전 경로로 복구한다.
- 동일 주소의 한글·영문 표기와 지점 접미사 후보를 안전하게 논리 병합한다.
- 본문의 명시적인 장소 목록과 source profile hint를 이용해 텍스트 장소 단서를 보강한다.
- 예약 플랫폼과 실제 장소 이름의 역할을 구분하도록 장소 단서 추론 규칙을 보강한다.
- live post 517, 520, 521 유형의 회귀 테스트를 추가한다.

## 안전 조건

- 같은 지역에 동명 지점이 여러 개면 자동 선택하지 않는다.
- 본문에 언급되지 않은 태그 프로필은 독립 장소로 추가하지 않는다.
- provider 후보에 없는 장소를 임의 생성하지 않는다.
- 기존 공개 API 계약을 유지한다.

## 제외 범위

- 영상 `thumbnail_url`을 OCR 입력으로 사용
- 기존 게시물 전체 자동 재파싱
- 장소 provider 변경
- 모호한 지점의 강제 자동 매핑

## 성공 기준 및 검증

- 부분 성공 게시물이 관리자에서 완전 성공으로만 표시되지 않는다.
- `Beaker`/`비이커`, `Tune`/`튠`, 종로 `마이너스` 유형은 유일한 검색 근거가 있을 때 해결된다.
- 발발 빈티지와 모소리처럼 복수 지점인 사례는 미해결 상태를 유지한다.
- 본문에 명시된 계정은 안전한 프로필 근거를 사용해 텍스트 단서로 회수할 수 있다.
- `pnpm build`, `./gradlew detekt`, `./gradlew test`, `./gradlew check`가 통과한다.
