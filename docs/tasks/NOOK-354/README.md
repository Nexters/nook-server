# NOOK-354 게시물 종료 시 실패 요약 알림

## 목적과 범위

작업마다 발송하던 알림을 게시물의 본문·장소·후속 작업이 모두 COMPLETED/FAILED가 된 뒤 한 건으로 묶는다.
워커가 10초 간격으로 후보를 100개씩 순회한다. PENDING/PROCESSING이 하나라도 있으면 기다리고,
전체 성공이면 알리지 않는다. 실패 후 마지막 다른 작업이 성공한 경우도 다음 순회에서 집계한다.

- 실패 단계와 안전한 사유별로 건수를 묶고, 전체·성공·실패 건수 및 마지막 실패 시각, 복구 링크를 전달한다.
- 원문 오류의 URL·토큰·본문을 노출하지 않도록 사유는 허용된 요약 문구로 분류한다. 미분류 오류는 관리자 상세 확인으로 안내한다.
- posts.parsing_alert_fingerprint에 전체 작업 상태·총 실행 번호·실패 시각의 해시를 보관한다.
  게시물 행 잠금과 짧은 트랜잭션으로 동시 발행을 직렬화하고 커밋 후 로그를 발행한다.
  이 칼럼은 ORM 갱신 대상에서 제외해 오래된 entity가 중복 방지 값을 덮어쓰지 못하게 한다.
  해시 갱신은 게시물 updated_at을 보존한다.
- 수동 재시도 종료 시 실패가 남으면 새 요약 한 건, 모두 복구되면 알림 없음. 기존 상태를 반복 조회해도 중복 발행하지 않는다.
- 장소 단서·예상 장소 수·처리 오류가 모두 없는 빈 결과는 제목을 확정하고 장소 0개로 정상 완료한다.
  단서가 있는데 검색 실패, 예상 장소 누락, OCR/provider 오류는 기존 실패·재시도 경로를 유지한다.
- API 게시물 저장 요청 ERROR 알림은 게시물 식별자가 생기기 전일 수 있어 기존 별도 알림을 유지한다.

## 제외 범위와 한계

관리자 UI/API 계약 변경, 성공 알림, 완료 게시물 재분석, 기존 실패 상태 일괄 보정은 하지 않는다.
실패 시각이 전부 NULL인 과거 작업은 소급 알리지 않는다. 실제 실패 시각이 있는 미해결 게시물은
새 기능 최초 가동 시 한 번의 통합 요약을 받을 수 있다.
DB의 중복 발행 방지는 재시작에도 유지되지만 로그 전달기의 장기 장애 및 DB 커밋 직후 프로세스 중단까지
전송을 보장하는 outbox는 아니다. Discord 전송 재시도 정책은 기존대로 유지한다.

## 성공 기준과 검증

- 진행 중/자동 재시도 대기 중 무알림, 마지막 작업 성공 뒤 실패 요약 1건, 전체 성공 무알림.
- 같은 단계·사유의 실패 여러 건을 합산하고 URL 등 원문 비밀값이 알림에 포함되지 않음.
- MySQL 8.4 동시 발행과 새 publisher 인스턴스에서도 중복 없음, 수동 재시도 회차 구분, updated_at 보존.
- 장소 정상 빈 결과 성공, 실제 검색/OCR 오류 실패 및 재시도 유지.
- 전체 Gradle check 통과: JVM 테스트 747건, 실패/오류/건너뜀 0건. Detekt와 모듈 의존 방향 검사 포함.
- 실제 MySQL 8.4 요약 알림 테스트 6건 통과: 동시 발행, 재시작 중복 방지, 최종 성공 뒤 집계, 재시도 회차, 롤백 및 수정 시각 보존.
- Python 전달기 테스트 19건 통과: 7개 실패를 단일 payload로 전송, 환경별 채널, 기존 개별 이벤트 제외.
- 로컬 동기화 폴더의 생성물 읽기 지연을 피하기 위해 임시 Gradle init 스크립트로 빌드 출력만 /tmp/nook354-builds로 옮겨 검증했다. 저장소 빌드 설정은 변경하지 않았다.
- git diff --check 통과. 실제 Discord 실패 알림 발송은 미실행. 원격 적용 상태는 아래 기록을 따른다.

## 배포와 롤백

1. 사용자 승인 후 dev DB에 ddl/up.sql을 선행 적용하고 API/worker를 검증한다.
2. live DDL과 배포는 별도 사용자 요청 후 진행한다. DDL은 MySQL 8.4 INSTANT 칼럼 추가이며 일회용이다.
3. 전달기는 새 summary 이벤트를 처리하도록 worker보다 먼저 갱신한다.
4. 롤백은 worker/전달기를 함께 이전 버전으로 복원한다. 필요할 때만 ddl/rollback.sql을 적용한다.
   칼럼 삭제는 중복 방지 이력을 지우므로 이후 재배포 시 기존 미해결 게시물이 다시 알림을 받을 수 있다.
