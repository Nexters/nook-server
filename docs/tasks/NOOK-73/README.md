# NOOK-73 그룹 저장 게시물 목록 메타데이터 확장

## 목적

그룹 상세 화면에서 그룹 소유자의 닉네임과 각 저장 게시물에 연결된 장소 개수를 표시할 수 있도록
그룹 내 저장 게시물 목록 응답을 확장한다.

## 범위

- 그룹 저장 게시물 목록 응답 최상위에 `ownerNickname` 추가
- 인증 사용자가 아니라 그룹의 `userId`를 기준으로 소유자 닉네임 조회
- 각 저장 게시물에 `placeCount` 추가
- 페이지 내 게시물의 장소 관계를 한 번에 조회해 장소 개수 계산
- 그룹 전용 application 결과와 presentation 응답 구성
- application, persistence 및 controller 회귀 테스트

## 제외 범위

- 다른 사용자의 그룹을 조회하기 위한 공개 또는 공유 권한 정책
- 소유자 프로필 이미지 등 추가 회원 정보
- 그룹 전체의 장소 합계
- 장소 상세 정보 목록
- 일반 저장 게시물 목록 API 계약 변경
- DB 스키마 변경

## 설계

그룹 게시물 조회는 일반 저장 게시물 조회 포트와 분리된 `GroupPostQueryPort`를 사용한다. 그룹 전용
결과에는 그룹 소유자 닉네임과 게시물별 장소 개수를 포함하며, 일반 저장 게시물 목록 응답은 기존
계약을 유지한다.

소유자 닉네임은 요청 사용자 ID를 그대로 사용하지 않고, 소유권 검증을 통과한 그룹의 `userId`로
회원을 조회한다. 따라서 추후 다른 사용자 그룹 조회 정책을 추가하더라도 응답 계약을 변경하지 않아도
된다.

게시물별 장소 개수는 현재 페이지의 원본 게시물 ID를 모아 `post_places`를 한 번에 조회한 뒤
게시물 ID별로 집계한다. 장소 관계가 없는 게시물에는 `0`을 반환한다.

## 성공 기준

- 그룹 저장 게시물 목록 응답에 실제 그룹 소유자의 `ownerNickname`이 포함된다.
- 모든 게시물 항목에 정확한 `placeCount`가 포함된다.
- 장소가 없는 게시물의 `placeCount`는 `0`이다.
- 여러 게시물의 장소 관계를 추가 쿼리 한 번으로 조회한다.
- 일반 저장 게시물 목록과 기존 pagination·정렬 계약이 유지된다.
- `./gradlew check`가 성공한다.

## 검증

```shell
./gradlew detekt
./gradlew test
./gradlew check
```

## 배포 및 롤백

DB 변경과 외부 시스템 변경은 없다. 애플리케이션 배포로 적용하며 문제가 있으면 이전 애플리케이션
버전으로 롤백한다.
