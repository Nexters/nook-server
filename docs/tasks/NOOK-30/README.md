# NOOK-30 사용자 메모 저장 경계 수정 및 편집 API

## 목적

게시물 메모를 공용 원본 게시물(`posts`)에서 사용자 저장 게시물(`user_saved_posts`)로 옮겨,
같은 원본을 저장한 사용자끼리 메모가 공유되지 않게 합니다. 사용자는 자신이 저장한 게시물의
메모만 변경하거나 삭제할 수 있습니다.

## 범위

- 게시물 생성 요청의 `memo`를 `user_saved_posts.memo`에 저장
- `posts.memo`의 기존 데이터를 사용자 저장 행으로 이관하고 공용 칼럼 제거
- 사용자 저장 게시물 메모 변경 API 추가
- 메모 소유권, 삭제, 길이 검증 테스트
- HTTP Client와 OpenAPI 계약 갱신

## 제외 범위

- 원본 게시물 제목·본문 편집
- 그룹 설명 편집
- 게시물 삭제

## API 계약

### 내 저장 게시물 메모 변경

```http
PATCH /api/v1/posts/{postId}/memo
Content-Type: application/json

{
  "memo": "다음 주 평일에 방문"
}
```

- `postId`는 `user_saved_posts.id`에 대응하는 사용자 소유 게시물 식별자입니다.
- `memo`는 최대 2,000자입니다.
- `memo`에 빈 문자열을 전달하면 빈 문자열을 메모 값으로 저장합니다.
- 기존 메모 삭제는 빈 문자열과 구분되는 명시적 `null`로 요청합니다.

```json
{
  "memo": null
}
```

- 소유하지 않은 `postId`도 존재 여부를 노출하지 않고 `POST_NOT_FOUND`(404)를 반환합니다.
- 성공 응답은 기존 변경 API와 동일한 `ApiResponse<Unit>` 형식을 사용합니다.

## 데이터 이관

`ddl/up.sql`은 다음 순서로 실행합니다.

1. `posts.memo`가 있고 연결된 `user_saved_posts.memo`가 비어 있는 행에만 기존 메모를 복사합니다.
2. 이미 사용자 메모가 있는 행은 덮어쓰지 않습니다.
3. 이관 후 `posts.memo`를 제거합니다.

하나의 원본 게시물에 여러 사용자가 연결되어 있으면 기존 공용 메모가 각 사용자의 비어 있는
메모에 복사됩니다. 이는 기존 사용자에게 보이던 값을 보존하면서 이후 사용자별 편집을 분리하기
위한 동작입니다.

`ddl/rollback.sql`은 공용 칼럼을 복원하고 원본별 사용자 메모 중 하나를 결정적으로 복사합니다.
여러 사용자 메모를 하나의 공용 칼럼으로 되돌리는 과정은 본질적으로 손실이 있으므로, 운영
롤백 전에 해당 원본들의 메모를 별도로 백업해야 합니다. rollback은 `user_saved_posts.memo`를
삭제하거나 변경하지 않습니다.

## 성공 기준 및 검증

- 생성 메모가 `user_saved_posts.memo`에만 저장됩니다.
- 메모 수정과 `null` 삭제는 요청 사용자가 소유한 저장 행에만 적용됩니다.
- 타인의 저장 게시물 수정은 404로 차단됩니다.
- 2,000자를 초과한 메모는 400으로 거절됩니다.
- persistence, application, controller 테스트가 존재합니다.
- `./gradlew check`가 성공합니다.
