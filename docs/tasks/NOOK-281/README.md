# NOOK-281 Instagram 태그 기반 장소 단서 교정 및 카드 검색어 보존

## 목적

Instagram 번호 카드의 상호명이 OCR에서 한두 자모 다르게 전사되어 지도 검색 후보를 만들지 못하거나,
번호 카드 복구 과정에서 모델이 만든 지역·업종·메뉴 검색어가 사라지는 문제를 해결한다.

## 원인

- Apify 응답의 `taggedUsers`에는 정확한 프로필 표시명과 사용자명이 있지만 현재 매핑에서 버리고 있다.
- 번호 카드 단서를 모델 단서보다 먼저 둔 뒤 상호명으로 중복 제거해 모델의 풍부한 검색어가 유실된다.
- OCR provider가 카드 구분자 `|`를 `ᅵ`, `ᆞ`, `·`, `•`로 전사하면 번호 카드를 인식하지 못한다.
- 주소 기반 한글 자모 비교는 명시 주소와 검색 후보가 모두 있어야 하므로 후보가 0건인 상호 오인식을 복구하지 못한다.

## 범위

- Apify `taggedUsers`의 표시명과 사용자명을 장소 파싱 job에 저장한다.
- 태그 프로필은 독립 장소로 추가하지 않고 기존 OCR·모델 단서의 이름 교정에만 사용한다.
- 한글 자모 유사도가 충분하고 태그 후보가 하나로 확정될 때만 장소명을 교정한다.
- 번호 카드와 모델 단서를 병합해 지역·업종·메뉴 검색어와 이미지 근거를 보존한다.
- OCR 카드 구분자 `ᅵ`, `ᆞ`, `·`, `•`를 지원한다.
- 쑨송, 송정, 호뎅, 흐릇 유형과 협찬 프로필 제외를 회귀 테스트한다.

## 제외 범위

- 특정 상호명 하드코딩
- 태그된 모든 프로필을 장소로 자동 등록
- Instagram 프로필 페이지 추가 크롤링
- 지도 검색 후보 수의 일괄 확대
- live 데이터 일괄 재파싱

## 성공 기준

- `쏟송`·`순송` 단서가 태그 표시명 `쑨송` 하나로 교정·병합된다.
- `호덱`과 `흐릿` 단서가 각각 `호뎅`, `카페흐릇`으로 교정된다.
- `송정 항정국밥 망원`처럼 모델이 만든 검색어가 번호 카드 복구 후에도 유지된다.
- `펩시코리아`처럼 OCR 장소 단서와 일치하지 않는 태그 프로필은 장소로 추가되지 않는다.
- 관련 단위 테스트와 `./gradlew check`가 통과한다.

## 검증

- `PlaceParsingResilienceTest`
- `ProcessPostContentParsingJobUseCaseTest`
- `ApifyInstagramMapperTest`
- `PostContentParsingPersistenceAdapterTest`
- `PlaceParsingPersistenceAdapterTest`
- `./gradlew detekt`
- `./gradlew test`
- `./gradlew check`

## 배포 및 롤백

애플리케이션 배포 전에 `ddl/up.sql`로 nullable 칼럼을 추가한다. 롤백 시 새 애플리케이션을 먼저 내린 뒤
`ddl/rollback.sql`로 칼럼을 제거한다. 기존 장소 파싱 job은 태그 힌트가 없는 상태로 이전 동작을 유지한다.
