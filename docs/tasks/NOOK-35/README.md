# NOOK-35 그룹 게시물 관리와 저장 시 그룹 지정

## 목적

사용자가 URL로 게시물을 저장할 때 선택한 그룹에 함께 연결하고, 저장 후에도 그룹 구성을
추가·제거·이동할 수 있게 합니다.

## 범위

- 기존 `POST /api/v1/posts` 요청의 선택적 `groupIds`
- 하나의 저장 게시물을 복수 그룹에 연결
- `GET /api/v1/groups/{groupId}/posts` 그룹 저장 게시물 목록
- `PUT /api/v1/posts/{postId}/groups` 저장 게시물 그룹 전체 재지정
- 게시물과 그룹의 현재 사용자 소유권 검증
- 생성과 그룹 연결의 단일 DB 트랜잭션
- HTTP Client, OpenAPI 및 회귀 테스트

## 제외 범위

- 그룹 CRUD
- 저장 게시물 자체 삭제
- 그룹 외부 공유
- 그룹 순서 수동 정렬

## API 계약

### 게시물 저장 시 그룹 지정

기존 요청과의 호환성을 위해 `groupIds`는 선택값이며 생략하면 그룹에 연결하지 않습니다.
중복 식별자는 한 번만 연결됩니다.

```json
{
  "url": "https://www.instagram.com/p/ABC123/",
  "memo": "주말에 방문",
  "groupIds": [1, 2]
}
```

### 그룹 저장 게시물 목록

```http
GET /api/v1/groups/{groupId}/posts?page=0&size=20
```

- NOOK-29 저장 게시물 목록과 같은 요약·pagination 계약을 사용합니다.
- 저장 시각 내림차순, 저장 게시물 식별자 내림차순으로 안정적으로 정렬합니다.
- 존재하지 않거나 다른 사용자의 그룹은 모두 `GROUP_NOT_FOUND`로 응답합니다.

### 저장 게시물 그룹 재지정

```http
PUT /api/v1/posts/{postId}/groups
Content-Type: application/json

{
  "groupIds": [1, 2]
}
```

- 전달한 목록이 게시물의 전체 그룹 구성을 대체합니다.
- 빈 목록은 모든 그룹 연결을 제거합니다.
- 동일한 요청을 반복해도 최종 그룹 구성은 같습니다.
- 존재하지 않거나 다른 사용자의 게시물은 `POST_NOT_FOUND`로 응답합니다.
- 하나라도 접근할 수 없는 그룹이면 `GROUP_NOT_FOUND`로 응답하고 기존 연결을 유지합니다.

첫 그룹이 없는 사용자는 그룹 생성 API로 그룹을 만든 뒤 생성 요청 또는 재지정 요청에 해당
식별자를 전달합니다.

## 데이터와 트랜잭션

- 기존 `group_posts`의 유니크 제약으로 같은 게시물의 같은 그룹 중복 연결을 방지합니다.
- 게시물 생성과 `user_saved_posts`, `group_posts` 저장은 하나의 짧은 DB 트랜잭션에서 처리합니다.
- 외부 게시물 provider와 미디어 저장 호출은 기존과 같이 DB 트랜잭션 전에 완료됩니다.
- 기존 테이블과 제약만 사용하므로 신규 DDL은 없습니다.

## 검증

- 그룹 ID 중복 정규화와 기존 그룹 미지정 요청 호환성
- 그룹·게시물 소유권 오류
- 생성 시 복수 그룹 연결과 실패 전 데이터 미생성
- 빈 목록 제거와 전체 재지정
- 그룹 목록 pagination과 정렬
- `./gradlew check`
