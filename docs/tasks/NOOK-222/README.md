# NOOK-222 카카오·네이버 간 동일 장소 중복 저장 방지

## 목적

카카오와 네이버가 같은 실제 장소를 서로 다른 외부 ID와 주소 형식으로 반환해도 하나의 공용
장소로 식별하여 지도 마커와 연관 게시물이 분리되지 않게 합니다.

## 범위

- provider별 외부 장소 ID를 공용 `place_id`에 연결하는 `place_provider_references`를 추가합니다.
- 기존 `provider + external_place_id` 일치를 가장 먼저 확인합니다.
- 새 외부 ID는 상호명 호환성, 도로명 핵심 주소 일치, 좌표 30m 이내를 모두 만족하는 장소가
  하나일 때만 기존 공용 장소에 연결합니다.
- 주소만 같은 건물의 다른 가게는 병합하지 않습니다.
- 자동 파싱과 사용자의 직접 장소 연결에 동일한 장소 식별 정책을 적용합니다.
- 기존 하프하우스 KAKAO/NAVER 중복 관계를 KAKAO 장소로 합치는 멱등 DML을 제공합니다.

## 제외 범위

- 장소명이 호환되지 않고 주소와 좌표만 유사한 장소의 자동 병합
- 여러 기존 장소가 동시에 일치하는 모호한 후보의 자동 병합
- 운영자용 임의 장소 병합 API 또는 UI
- 전체 기존 장소에 대한 무조건적인 fuzzy 일괄 병합

## 성공 기준

- `DYhhhgNktcp`, `Dbj3fgpiTna` 게시물의 하프하우스가 같은 `place_id`를 참조합니다.
- 두 게시물은 한 장소의 연관 게시물로 함께 조회되고 지도 마커는 하나만 표시됩니다.
- `서울`/`서울특별시`와 층·호 상세 표기 차이가 장소 중복을 만들지 않습니다.
- 같은 건물의 이름이 다른 가게는 별도 장소로 저장됩니다.
- 관련 테스트와 `./gradlew check`가 성공합니다.

## 적용 순서

1. `ddl/up.sql`을 적용합니다.
2. `dml/up.sql`을 적용합니다.
3. 애플리케이션을 배포합니다.

롤백할 때는 애플리케이션을 먼저 이전 버전으로 되돌린 뒤 `dml/rollback.sql`,
`ddl/rollback.sql` 순서로 적용합니다.

## 재현 데이터

- KAKAO: `places.id=928`, 외부 ID `170705999`, `서울 강남구 강남대로84길 13`
- NAVER: `places.id=929`, 외부 ID
  `0048087adc7f0ab0a6fbcf2f65751264bfca5212a9fdd7574f8161be6d9e9a07`,
  `서울특별시 강남구 강남대로84길 13 강남역 KR 타워 1층, 2층`
- 두 좌표 간 거리는 약 10m입니다.

## 검증 결과

- 개발 DB에 `ddl/up.sql`, `dml/up.sql`을 적용했습니다.
- KAKAO와 NAVER 외부 ID가 모두 공용 `place_id=928`을 가리킵니다.
- `Dbj3fgpiTna`, `DYhhhgNktcp`, `DZWPvUMgTQH`의 하프하우스 관계가 모두
  `place_id=928`로 정리됐습니다.
- 같은 사용자의 저장 게시물 3개도 모두 `place_id=928`을 참조합니다.
- 데이터 보정 DML을 재실행해도 같은 결과가 유지되는 것을 확인했습니다.
- 지도 영역 API에서 하프하우스 마커는 `place_id=928` 한 개만 반환됐습니다.
- 장소 상세 API에서 하프하우스의 연관 게시물 3개가 반환됐습니다.
- 기존 중복 `place_id=929`는 관계와 별칭에서 제외되어 사용자 장소 상세에서는 404가 반환됩니다.
- `./gradlew check`가 성공했습니다.
