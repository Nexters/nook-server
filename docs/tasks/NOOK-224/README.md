# NOOK-224 상호명·인접 번지 차이의 동일 장소 중복 병합

## 목적

카카오와 네이버가 동일한 가게를 상호명 지점 표기 또는 인접 도로명 건물번호 차이로 반환해도
하나의 공용 장소로 식별하여 지도 마커와 연관 게시물이 분리되지 않게 한다.

## 범위

- 핵심 도로명 주소가 같으면 기존 상호명 포함 관계와 30m 이내 판정을 유지한다.
- 도로명은 같지만 건물번호가 다르면 서로 다른 provider, 정규화 상호명 완전 일치, 10m 이내,
  건물번호 차이 2 이하 조건을 모두 만족할 때만 같은 장소 후보로 판정한다.
- 여러 기존 장소가 일치하면 기존 resolver 정책대로 자동 병합하지 않는다.
- 동일 장소로 판정한 provider 외부 ID를 하나의 canonical `place_id`에 등록한다.
- 기존 보후밀과 감나무집기사식당 중복 장소의 게시물, 저장 게시물, 태그, 북마크와 provider reference를
  canonical 장소로 이동하는 멱등 DML을 제공한다.
- 같은 사용자가 두 장소에 서로 다른 메모를 작성했으면 빈 값이 아닌 메모를 줄바꿈으로 합쳐 보존한다.

## 제외 범위

- 도로명이 다른 장소의 자동 병합
- 좌표만 가까운 장소의 자동 병합
- 상호명이 다른 같은 건물 또는 인접 번지 매장의 자동 병합
- 사진 유사도 기반 장소 판정
- 전국 기존 장소의 무조건적인 fuzzy 일괄 병합
- 운영자용 수동 병합 UI
- DB 스키마 변경

## 성공 기준

- `보후밀 효창공원 / 효창목2길 30`과 `보후밀 / 효창목2길 30 1층 일부호`가 같은 장소로 식별된다.
- `감나무집기사식당 / 연남로 23`과 `감나무집기사식당 / 연남로 25`가 같은 장소로 식별된다.
- 같은 건물 또는 인접 번지의 이름이 다른 가게와 같은 provider의 별도 장소는 병합되지 않는다.
- 기존 두 중복 쌍의 저장 게시물과 북마크가 canonical 장소에 보존된다.
- 각 provider reference가 canonical 장소를 가리키고 지도에는 장소별 마커가 하나만 표시된다.
- DML을 재실행해도 같은 결과가 유지되며 rollback 스크립트가 제공된다.
- 관련 테스트와 `./gradlew check`가 성공한다.

## 데이터 정리 대상

| 장소 | canonical | duplicate |
| --- | --- | --- |
| 감나무집기사식당 | KAKAO `1641347883` (`places.id=717`) | NAVER `933ec67e8b4be972a8373632113c5c8dce13debda1603834a6da65435206f3b3` (`places.id=864`) |
| 보후밀 | KAKAO `2089608233` (`places.id=746`) | NAVER `3e5d4b557a6b8aaef26e2337a16c1593102937a8c87011d5a4d5e4eb0427d677` (`places.id=853`) |

중복 `places` 행은 삭제하지 않는다. provider reference와 사용자에게 노출되는 관계만 canonical 장소로
이동하여 rollback 시 원래 장소 식별자를 다시 사용할 수 있게 한다.

## 적용 순서

1. `dml/up.sql`을 적용한다.
2. 애플리케이션을 배포한다.
3. provider reference, 관계 수, 지도 마커와 장소 상세 연관 게시물을 검증한다.

롤백할 때는 애플리케이션을 이전 버전으로 되돌린 뒤 `dml/rollback.sql`을 적용한다. 병합 시 서로 다른
두 메모를 합친 경우 rollback은 합친 메모를 양쪽 북마크에 보존하며 문자열을 자동 분리하지 않는다.

## 검증 결과

- 개발 DB에 `dml/up.sql`을 적용했다.
- 감나무집기사식당의 KAKAO/NAVER reference가 모두 `place_id=717`을 가리킨다.
- 보후밀의 KAKAO/NAVER reference가 모두 `place_id=746`을 가리킨다.
- 감나무집기사식당의 원본 게시물 2건과 저장 게시물 2건이 `place_id=717`로 정리됐다.
- 보후밀의 원본 게시물 3건과 저장 게시물 7건이 `place_id=746`으로 정리됐다.
- 동일 사용자의 서로 다른 장소 메모는 줄바꿈으로 합쳐 보존됐다.
- `dml/up.sql`을 두 번 실행해도 reference, 관계 수와 메모가 변하지 않았다.
- `dml/rollback.sql` 적용 시 NAVER reference와 원래 게시물 관계가 중복 장소로 복구됐다.
- rollback 검증 후 `dml/up.sql`을 다시 적용해 개발 DB의 최종 상태를 병합 상태로 유지했다.
- 개발 지도 API에서 감나무집기사식당은 `place_id=717`, 보후밀은 `place_id=746` 마커만 반환됐다.
- 사용자 1의 장소 상세에서 감나무집기사식당과 보후밀의 연관 게시물이 각각 2건 반환됐다.
- 기존 중복 `place_id=853`, `place_id=864`의 장소 상세는 404를 반환했다.
- `./gradlew clean check`가 성공했다.
