# 저장 장소 검색에 메모·태그 키워드 추가

## 목적

저장하면서 남긴 개인 메모와 장소에 표시되는 태그명으로 저장 장소를 다시 찾는다.

## 범위

- 기존 장소명·주소·카테고리 부분 일치 검색에 본인의 장소 북마크 메모를 추가한다.
- 장소의 `representative_tags`에 포함된 활성 카탈로그 태그의 `display_name`을 검색한다.
- 목록, 전체 건수, 아카이브별 매칭 장소 수에 동일한 검색 조건을 적용한다.
- 기존 접근 권한, 그룹 필터, 페이지네이션 및 정렬을 유지한다.
- API 검색 설명과 HTTP Client 예제를 갱신한다.

## 제외 범위

- 자연어·의미 기반 검색, 별도 검색 가중치, 메모 전문 응답
- 비활성 태그, 내부 태그 코드, 추론용 키워드 및 화면에 표시되지 않는 게시물별 태그 검색
- API 요청·응답 필드 변경, DB 스키마 변경, FE UI 변경

## 설계

사용자가 승인한 계획에 따라 기존 LIKE 부분 일치 및 특수문자 이스케이프를 유지한다.
메모는 사용자별 `user_place_bookmarks.memo`로 제한한다. 태그는 활성 카탈로그의 표시명과
장소의 대표 태그 JSON을 EXISTS/JSON_CONTAINS로 비교해 여러 태그가 매칭돼도 장소를 중복 반환하지 않는다.
이름 매칭 → 주소 매칭 → 그 외 매칭 순서와 이름·ID 보조 정렬을 유지한다.
그룹 검색에서도 동일한 본인 메모와 장소 대표 태그를 사용한다.

## 성공 기준 및 검증

- 메모 또는 활성 대표 태그 표시명 키워드로 장소를 찾는다.
- 다른 사용자의 메모, 비활성 태그 및 내부 태그 코드는 매칭되지 않는다.
- 메모가 없는 장소도 기존 이름·주소·카테고리로 검색된다.
- 중복 태그·저장 관계에도 장소 목록 및 전체·아카이브별 건수가 일치한다.
- 그룹 필터, 접근 권한 및 기존 정렬과 페이지네이션을 유지한다.
- MySQL 8.4 실제 쿼리 실행 테스트와 기존 검색 테스트 4건 통과.
- 전체 Detekt 및 모듈 의존 방향 검사 통과.
- 전체 테스트 844건 중 843건 통과, 기존 `ParsingSummaryMySqlTest` 1건 실패.
- 실패 테스트: `legacy fingerprint migrates without republishing an existing failure`, 146행.
  변경 없는 `origin/main` (`0c38eddd`)을 임시 디렉터리에 추출해 단독 실행해도 동일하게 실패했다.
  이번 검색 변경과 무관한 기존 파싱 알림 문제로 확인했으며 이 이슈에서는 수정하지 않는다.
- `./gradlew check --max-workers=2 -Dorg.gradle.jvmargs='-Xmx2g -XX:MaxMetaspaceSize=768m'` 실행.
  기본 Gradle JVM은 GC thrashing으로 중단되어 검증 실행에만 메모리 옵션을 지정했다.
  전체 `check`는 위 기존 테스트 실패 때문에 통과하지 못했다.
- 검증일: 2026-10-11 KST. `git diff --check` 통과.
