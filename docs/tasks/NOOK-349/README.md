# NOOK-349 파싱 실행 안전성

## 목적

후속 작업을 미리 일괄 선점한 뒤 순차 실행하면 실제 시작 전에 처리 제한시간이 소진될 수 있다.
또한 재선점 후 늦게 끝난 실행이 최신 실행의 상태나 데이터를 변경할 수 있었다.

## 범위

- 후속 작업은 실제 실행 직전에 한 건씩 선점한다.
- job ID, PROCESSING 상태, 단조 증가하는 attempt 번호를 잠금 안에서 확인한다.
- 미디어, 썸네일, 태그의 DB 변경만 보호된 짧은 트랜잭션 안에서 실행한다.
- 완료·실패·재시도 전이에도 같은 소유권 검사를 적용한다.
- 콘텐츠/장소 작업의 제한 조회는 대기 시각 및 처리 만료 조건을 DB에 적용한 뒤 제한한다.

## 제외 범위

전체 재분석 회차 및 서로 다른 job 간 결과 우선순위는 NOOK-351 범위다.
외부 서비스 호출 자체의 exactly-once 실행은 보장하지 않는다.

## 검증

`ParsingExecutionMySqlTest`와 `ProcessParsingFollowUpJobsUseCaseTest`에서 동시성과 소유권, 실행 순서를 검증한다.
