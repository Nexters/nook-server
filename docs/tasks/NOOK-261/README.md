# NOOK-261 게시물 파싱 진행률을 실제 마일스톤 기반 단조 증가 방식으로 개선

## 목적

게시물 처리 진행률을 실제 콘텐츠·장소 파싱 단계에 연결하고, 중간 저장이나 재시도에도 사용자에게 이미
노출된 진행률이 감소하지 않도록 한다.

## 범위

- 콘텐츠 조회, 커버 제목, 콘텐츠 추론, 저장 단계를 콘텐츠 마일스톤으로 기록한다.
- 텍스트 단서, 텍스트 장소 해결, 이미지 OCR, 이미지 단서, 이미지 장소 해결, 저장 단계를 장소 마일스톤으로 기록한다.
- 각 마일스톤 안에서는 예상 소요 시간을 이용해 제한된 구간만 보간한다.
- 재시도 전 현재 보간값을 확정하고 다음 시도에서 더 이전 단계로 돌아가지 않는다.
- 기존 `processingPercent` API 필드와 상태 계약을 유지한다.

## 제외 범위

- 클라이언트 변경
- 별도 진행률 API
- provider 변경
- 기존 완료 작업 backfill

## 진행률 기준

- 콘텐츠: 조회 `15~25`, 커버 제목 `25~32`, 추론 `32~42`, 저장 `42~45`
- 장소: 텍스트 단서 `60~66`, 텍스트 해결 `66~74`, 이미지 OCR `74~82`, 이미지 단서 `82~87`,
  이미지 해결 `87~93`, 저장 `93~95`
- 완료: `100`

선택 단계가 생략되면 다음 실행 마일스톤의 시작값으로 이동한다. 완료 전에는 `95`를 초과하지 않는다.

## 스키마

두 parsing job 테이블에 현재 마일스톤, 마일스톤 시작 시각, 확정 진행률을 추가한다. 신규 칼럼의 기본값으로
기존 대기 작업을 각각 콘텐츠 `5`, 장소 `50`에서 안전하게 시작하며 완료 데이터 backfill은 하지 않는다.
