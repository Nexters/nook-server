# NOOK-361 장소 0개 정상 저장과 경고 요약

## 목적

장소 분석 결과가 0개인 게시물도 정상 저장한다. 라이브 919번은 장소 저장 마지막 단계에서
빈 목록으로 PlaceTagsRequestedEvent를 생성하면서 예외가 발생해 완료 상태와 진단이 롤백됐다.
태그 대상이 없으면 후속 태그 작업을 만들지 않고 장소 파싱 완료 및 진단을 커밋한다.

## 범위와 성공 기준

- 장소 0개 완료는 실패나 자동 재시도 대상으로 만들지 않는다. 기존 장소가 있는 태그/썸네일 흐름은 유지한다.
- 관리자 게시물 정보 및 처리 상세에 노란색 ‘장소 없이 저장됨’ 경고를 표시한다.
- 경고 조건은 장소 파싱 COMPLETED, 저장 개수 진단이 기록됨, 현재 연결된 장소 0개다.
  진행 중/실패 또는 과거 진단 미기록은 성공으로 추측하지 않는다. 수동 매핑이 있으면 경고하지 않는다.
- 모든 작업이 COMPLETED/FAILED로 종료된 뒤 게시물 단위 요약을 생성한다.
- 실제 실패가 없고 장소가 없으면 WARN `post.parsing.summary_warning`으로 전달한다.
- 다른 작업 실패가 함께 있으면 기존 ERROR `post.parsing.summary_failed` 한 건에 장소 경고를 포함한다.
- 기존 fingerprint와 게시물 잠금/커밋 후 발행을 재사용해 반복 수집과 동시 발행의 중복을 막는다.
  새 재시도 회차가 끝나면 결과에 따라 새 요약을 보낼 수 있다.
- 전달기는 새 경고 이벤트만 WARN 전달 대상으로 추가한다. 일반 WARN 로그는 전달하지 않는다.
  dev/live의 기존 파싱 알림 채널과 처리 상세 링크를 사용한다.
- 게시물 전환 시 교정/수정 다이얼로그도 게시물 ID를 기준으로 다시 초기화해 이전 대상의 입력값을 남기지 않는다.
- 이전 요청대로 게시물 정보 제목 아래 원본 인스타 URL과 새 탭 링크를 표시한다.
  사용자가 취소한 알림의 원본 링크 추가는 제외한다.

## 알림 예시

장소 0개, 나머지 정상:

> [live] 게시물 #919 · 장소 없이 저장됨
> 게시물이 정상 저장되고 모든 처리 작업이 완료됐습니다.
> 전체 작업 7 / 성공 7 / 실패 0
> 확인 필요 · 장소 없이 저장됨
> 연결된 장소가 0개입니다. 원문을 확인해 필요한 장소를 연결해 주세요.

장소 0개, 미디어 1건 실패:

> [live] 게시물 #919 · 처리 완료 — 일부 실패
> 미디어 저장: 다운로드 실패 (1건)
> 확인 필요 · 장소 없이 저장됨

작업 개수는 실제 생성된 작업만 센다. 장소 0개 때문에 생략한 태그/썸네일 작업은 실패 건수가 아니다.

## 계약과 운영

API 응답/요청 계약과 DB 스키마는 변경하지 않는다. DDL은 필요 없다.
새 전달기와 워커를 함께 배포해야 WARN 이벤트가 알림에 전달된다.
기존 실패 게시물의 상태나 데이터는 직접 보정하지 않는다. 919번 등은 배포 후 재시도가 필요하다.
새 경고 조건에 해당하는 기존 완료 게시물도 다음 수집에서 최초 경고 대상이 될 수 있다.
이번 변경은 Discord 전달 성공 보장 방식이나 기존 요약의 재시도 정책을 변경하지 않는다.

## 검증

- MySQL 8.4: 빈 장소 결과의 완료/진단 커밋, 태그/썸네일 작업 미생성.
- 요약: 진행 중 대기, 동시 발행 및 반복 수집 중복 방지, 실패+경고 통합, 롤백, 새 재시도 회차,
  현재 매핑 존재 및 진단 미기록 제외.
- Python 전달기: 22건 성공. dev/live 경고 채널, 노란색 요약, 실패+경고 한 건 통합 포함.
- 관리자 웹 빌드 성공. 기존 번들 크기 경고만 발생.
- 인앱 브라우저 모의 API: 게시물 정보→처리 상세의 0개 경고, 처리 중 경고 없음,
  장소 1개 경고 없음, 게시물 정보 원본 URL 및 새 탭 속성 확인. 교정창 열기/취소와 게시물 전환 후 선택값 초기화 확인, 콘솔 오류 없음. 실제 운영 데이터를 수정하지 않았다.
- 전체 Gradle check 성공: JVM 760건, 실패/오류/건너뜀 0건. Detekt 및 모듈 의존 방향 포함.
- 구현 및 검증 완료. PR/배포/라이브 재시도는 아직 진행하지 않았다.
