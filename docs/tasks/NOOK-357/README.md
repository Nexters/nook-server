# NOOK-357 부분 완료의 장소별 결과

## 목적과 근거

부분 완료 6/7만 표시하면 어느 항목이 저장됐고 어느 단서가 미해결인지 확인하기 어렵다.
라이브 901번은 expected=7, extracted=6, resolved=6, unresolved=[]이며 실행 상태는 COMPLETED,
결과는 PARTIAL이다. 898번은 expected=7, extracted=6, resolved=5이고 버드나무집의 근거 불일치
미해결 단서 1개가 남아 있다. 숫자 차이만으로 이름 없는 나머지 항목의 실제 실패 원인을 추정하지 않는다.

## 범위와 성공 기준

- 게시글 정보와 처리 상세에 공통 장소별 처리 결과를 표시한다.
- 예상 수, 추출 수, 파싱 당시 저장 수를 각각 표시하고 후속 작업 건수와 구분한다.
- 현재 저장된 장소의 이름/주소/장소 상세 링크, 미해결 단서의 이름/주소/단계/사유를 나눠 표시한다.
- 미해결 사유는 한국어 요약과 펼침 상세(기록된 사유, 검색어, 원문 이미지 번호/근거)로 제공한다.
- 예상 수에서 저장 수와 기록된 미해결 단서 수를 제외하고 남는 양수는 '예상 수 기준 결과 미확인'으로
  표시한다. 예상은 추정치임을 알리고 이름/사유가 기록되지 않았음을 설명한다.
- 파싱 진단과 현재 매핑은 별도 정보다. 수동 교정 여부 또는 개수 차이가 있으면 차이를 설명한다.
  진행 중/실패한 실행은 진단이 마지막으로 기록된 값일 수 있음을 명시한다.
- 본문 COMPLETED를 '본문 완료'로 표시한다. 처리 작업이 끝나도 장소 결과가 PARTIAL이면
  '장소 일부 미해결'을 표시하며, 일부 작업이 실패하면 '일부 실패'로 표시한다.
- 완료 탭 이름을 '실행 완료'로 바꿔 장소가 모두 해결됐다는 의미와 구분한다.
- 게시글 정보의 매핑 목록 중복을 제거하고 기존 매핑 교정 동작은 같은 결과 구역에서 유지한다.

## 계약과 제외 범위

복구 작업 응답에 선택 필드 jobs[].outcome을 추가한다. 장소의 COMPLETED/PARTIAL 진단값이며
기존 status/재시도/오류 계약은 유지한다. 장소 정보/미해결 근거는 기존 게시글 상세 API를 재사용한다.
DB 변경은 없다. 파싱 정책, 자동 복구, 작업 상태/실패 이력 보정, 알림 정책은 변경하지 않는다.
별도로 발견한 'Place tag targets must not be empty' 저장 버그의 수정은 이번 화면 개선 범위에 포함하지 않았다.
과거 기록에 없는 미해결 장소명이나 실제 원인은 복원하지 않는다.

  정상 0곳 완료 사례, 게시글 정보/처리 상세, 미해결 근거 펼침, 매핑 교정 다이얼로그를 확인했다.

- 이번 검증은 로컬 모의 데이터이며 실제 게시글 상태/매핑은 수정하지 않았다.
