# NOOK-377 공유 아카이브를 추가한 사람 조회

이슈: https://linear.app/nooknook/issue/NOOK-377

## 목적과 확정 정책

2026-10-19 FE 코멘트는 `GET /api/v1/groups`의 내 아카이브 정보에 추가한 사람 목록을 요청했다.
2026-10-21 사용자는 인원수·미리보기와 별도 목록 API의 추가 로드를 선택했다.

- 소유자·구독자·유효한 공유 링크 열람자에게 같은 아카이브의 현재 추가한 사람을 제공한다.
- 공유 링크를 열기만 한 사용자와 원본 소유자는 포함하지 않는다. 참조형 구독 관계만 집계한다.
- 같은 사용자의 여러 공유 링크 구독은 한 명으로 집계한다. 탈퇴 회원과 삭제된 아카이브,
  해제/만료된 링크의 구독은 기존 공유 아카이브 접근 정책과 동일하게 제외한다.
- 닉네임·프로필 이미지만 읽기 전용으로 공개한다. 사용자 ID·이메일·로그인 정보·구독 ID를 노출하지 않는다.
- 현재 유효한 구독의 최근 추가 시각 내림차순, 동일 시각은 내부 회원 ID 내림차순으로 정렬한다.
  미리보기와 전체 목록은 같은 순서를 사용하며, 최근 추가 시각은 같은 회원의 유효 구독 중 최댓값이다.

## 구현 범위

- `GroupResponse`에 `subscriberCount`, `subscriberPreview`(최대 3명)를 추가한다.
  내/공유받은 목록, 소유 그룹 목록, 공개 공유 정보, 그룹 수정 응답에서 조회 상태를 제공한다.
  새 그룹 생성은 0명·빈 배열이다. 기존 endpoint·필드·오류 계약은 유지한다.
- 소유 그룹과 공유받은 그룹을 합친 뒤 summary를 한 번의 쿼리로 조회한다.
  DB에서 그룹별 중복 제거·집계·ROW_NUMBER 상위 3명 제한을 적용해 전체 명단을 응답에 싣지 않는다.
- 새 목록 API는 그룹 ID 기준 소유자/구독자의 읽기 권한 또는 공유 토큰의 활성 상태를 먼저 검증한다.
- 목록은 page=0, size=20을 기본값으로 쓰며 size는 1~100이다. 응답은 기존 페이지 구조를 따른다.
- 기존 테이블·인덱스만 사용한다. 새 entity·DDL·데이터 변경은 없다.

## API

- `GET /api/v1/groups` 및 `GET /api/v1/groups/owned`: 기존 응답에 인원수·미리보기 추가.
- `GET /api/public/v1/groups/{token}`: 같은 summary 추가.
- `GET /api/v1/groups/{groupId}/subscribers?page=0&size=20`: 로그인한 소유자·현재 구독자.
- `GET /api/public/v1/groups/{token}/subscribers?page=0&size=20`: 유효한 링크 열람자; 로그인 불필요.

실제 프로필 이동·사용자 제거·구독 취소 API는 추가하지 않는다.

## 성공 기준과 검증

- 실제로 추가한 활성 사용자만 중복 없이 나오며 소유자·링크 방문자·탈퇴 회원은 제외된다.
- 공유 해제·만료·구독 삭제·회원 탈퇴·그룹 삭제가 현재 count/preview/page에 반영된다.
- 소유/공유 조회의 summary와 목록 정렬·인원수가 일치하고, 미리보기는 3명을 넘지 않는다.
- 권한 없는 사용자는 그룹 ID로 접근하지 못하고 무효/만료/해제 토큰도 기존 오류로 차단된다.
- 페이지 경계·마지막/빈 페이지·프로필 이미지 null 및 기존 API 응답 호환성을 확인한다.
- 단위·H2·MVC 테스트 **913개 통과**(실패·오류·skip 0), Detekt·모듈 의존 검사와 `git diff --check` 통과.
- 최신 main `5795789d`(NOOK-413 포함)에 통합한 상태에서 최종 검증했다.
- Docker/MySQL 컨테이너 테스트·브라우저 조작·외부 서비스 호출은 실행하지 않는다.
