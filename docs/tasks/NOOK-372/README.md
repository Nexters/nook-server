# NOOK-372 파싱 후속 작업 큐 제한 병렬 처리

## 목적

미디어 저장, 장소 썸네일, 태그 저장 중 하나의 외부 I/O가 길어질 때 후속 작업 큐 전체가
직렬로 대기하는 현상을 완화한다.

## 범위

- 한 dispatcher 실행 안에서 설정된 동시성만큼 후속 작업을 병렬 처리한다.
- 실행 직전 작업만 claim해 processing timeout이 실행 대기 시간에 소모되지 않게 한다.
- 작업별 완료, 재시도, 실패 상태 기록을 독립적으로 유지한다.
- 기본 동시성은 2로 두고 환경 변수로 조정할 수 있게 한다.
- 종료 시 실행 중인 작업을 최대 60초 기다린다.

## 제외 범위

- provider별 호출 제한 및 비즈니스 규칙 변경
- 큐 저장소 교체
- 재시도 횟수와 backoff 정책 변경

## 성공 기준과 검증

- 두 작업이 설정된 동시성 안에서 동시에 실행된다.
- 한 작업의 실패가 같은 wave의 다른 작업 완료를 막지 않는다.
- batch size와 기존 claim/attempt 소유권 규칙을 유지한다.
- 관련 테스트와 `./gradlew check`가 성공한다.
- develop 배포 후 Worker health와 queue age를 확인한다.
