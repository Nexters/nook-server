# NOOK-343 사용자 행동 분석 이벤트 및 어드민 대시보드

## 목적

서버 API에서 확인 가능한 사용자 행동을 일관된 이벤트로 기록하고 가입, 저장 활성화, 재방문 흐름을
어드민 시각화 대시보드에서 확인한다.

## 범위

- 신규 회원 생성, 게시물 저장, 명시적 장소 저장 성공을 이벤트로 기록한다.
- 아카이브 첫 페이지, 게시물 상세, 장소 상세, 지도 영역 조회 성공을 이벤트로 기록한다.
- 가입은 회원별 1회, 저장 상태 전환 및 성공한 조회 관측은 발생 건별로 기록한다.
- 가입 cohort의 저장 활성화와 D1, D7, D30 재방문을 집계한다.
- 기간 필터와 별도의 활성 기준일을 두고 해당 날짜의 DAU, 최근 7일 WAU, 최근 30일 MAU를 집계한다.
- 어드민에서 기간과 활성화 저장 개수를 선택하고 퍼널, 날짜별 DAU 추이, 재방문 행동을 시각적으로 확인한다.
- 전체 활동 회원의 이벤트별 회원 수·건수, 저장 개수 분포와 1/3/5/10개 달성률을 확인한다.
- 기간 내 저장한 동일 콘텐츠의 후일 상세 조회, 활성화일별 재방문 히트맵을 확인한다.
- DAU·WAU·MAU, 기간 고유 회원, 날짜별 그래프 및 행동 막대에서 해당 조건의 모든 회원을 페이지로 조회한다.
- 회원을 펼치면 발생 시각, 이벤트, 대상 관리 링크를 시간순으로 확인한다.
- 기간 활동과 가입자 선정 기간(`from`~`to`)을 후속 관측 종료일(`observationEnd`)과 분리한다.
- 최초·최종 적재 시각, 최초 기록 이전 미관측, 관측 대기, 이전 중복 제거 기록을 구분한다.

## 제외 범위

- 앱 최초 실행 `first_open`
- 지도에서 실제 장소를 선택한 `map_place_select`
- 모바일 클라이언트 계측, 범용 수집 API와 외부 분석 SaaS 연동
- 기존 데이터의 이벤트 백필

## 이벤트 기준

- `sign_up`: 기존 로그인과 구분되는 신규 회원 생성
- `post_save`: 새로운 사용자 저장 게시물 생성 또는 삭제 상태 복원
- `place_save`: 사용자 요청으로 장소 북마크가 미저장 상태에서 저장 상태로 전환
- `archive_view`: 저장 게시물 또는 그룹 콘텐츠 첫 페이지 조회 성공
- `post_view`: 사용자가 소유한 저장 게시물 상세 조회 성공
- `place_view`: 사용자가 접근할 수 있는 장소 상세 조회 성공
- `map_view`: 사용자의 지도 영역 조회 성공

게시물 저장 과정에서 자동 생성되는 장소 북마크는 `place_save`로 기록하지 않는다.

이전 버전은 저장을 회원·대상별 평생 1회, 조회를 회원·대상·한국 날짜별 1회로 중복 제거했다.
보완 버전은 `sign_up`의 기존 키를 유지하고 나머지는 `RAW:{eventId}` 키를 사용한다.
저장은 기존 유스케이스의 실제 상태 전환 조건을 유지하므로 이미 저장된 대상에 대한 단순 재요청은 제외된다.
과거에 제거된 반복 기록은 복원하지 않으며 기간에 이전 기록이 섞이면 화면에 경고한다.
이벤트 ID의 중복 저장 방지는 유지한다. 새 요청은 새 ID이므로 조회 재시도·자동 호출과 실제 방문을 구분하지 못한다.
`map_view`는 실제 장소 선택이 아니라 지도 API를 통한 탐색의 대체 지표다.

## 보완 집계 계약

- 모든 일자와 날짜 경계는 KST이며 DB 조회는 `[시작 00:00, 종료 다음 날 00:00)`이다.
- 기존 응답 필드를 유지하고 `report`를 추가했다. `observationEnd` 생략 시 기존처럼 `to`를 사용한다.
- 기간 조회는 최대 90일, 시작일부터 후속 관측 종료일까지 최대 365일이다. 미래 관측일은 오늘로 제한한다.
- 기간 고유 활동 회원은 해당 기간 이벤트의 고유 회원 수다. DAU를 합산한 값이 아니다.
- ‘기간 내 가입 기록 없는 회원’은 기존 회원의 확정 판정이 아니다. 계측 전 가입 기록이 없을 수 있다.
- 저장 분포는 기간 활동 회원 전체가 분모이며 0개도 포함한다. 회원별 `(targetType, targetId)`로 중복 제거한다.
- 저장 대상 수는 현재 보관 수가 아닌 기간 동안 저장한 서로 다른 대상 수다. 삭제 후 재저장도 대상 수는 1개다.
- 동일 콘텐츠 재조회는 기간 내 저장한 `(회원, 대상 종류, 대상 ID)`의 최초 저장일보다 늦은 날짜의 상세 조회다.
- 가입자 활성화 및 재방문은 후속 관측 종료일까지 본다. 기간 밖 가입자는 이 cohort에 포함하지 않는다.
- 히트맵의 분모는 D1/7/30 날짜가 도래한 활성 회원이다. 미도래 셀은 0%가 아닌 관측 대기다.
- 오늘은 진행 중인 날짜다. 당일 수치와 당일 도래한 retention은 하루가 끝날 때까지 변할 수 있다.
- 전역 최초·최종 시각은 연속 수집이나 계측 시작 시점을 보장하지 않는다. 미관측과 실제 무활동은 구별에 한계가 있다.
- DAU/WAU/MAU 요청과 기간 요청을 분리해 한쪽 필터 오류·로딩이 다른 영역을 지우지 않는다.

## 배포 및 운영 주의

- 이번 보완에는 추가 DDL이 없다. 기존 `analytics_events`와 유니크 제약을 그대로 사용한다.
- 이전 서버로 롤백하면 신규 원시 기록은 유지되나 이후 기록은 다시 이전 중복 제거 정책을 따른다.
- 집계는 제한 기간의 원시 이벤트를 메모리에서 처리한다. 트래픽 증가 시 시간 인덱스·일별 집계 테이블과
  DB 집계 전환을 별도 검토한다. 이번 작업은 소규모 현재 사용량 대상이며 부하 성능 검증은 별도다.
- 개발·라이브 배포 및 PR 생성은 이번 로컬 구현과 별도 리뷰 후 진행한다.

## 시각화 및 활동 상세 (2026-09-09)

### 성공 기준

- 일간·주간·월간 카드 클릭 시 카드 아래에 동일한 KST 1·7·30일 범위의 회원 목록이 펼쳐진다.
- 카드와 상세 인원은 가입 포함 동일 이벤트의 고유 회원 수이며, 저장순 상위 100명 제한을 사용하지 않는다.
- 날짜별 DAU와 행동 막대 클릭 시 선택 날짜 또는 기간·이벤트 조건의 회원을 조회한다.
- 회원을 펼치면 해당 조건의 이벤트·시각·대상이 나오며 회원 목록과 이벤트 모두 페이지 이동한다.
- 필터 변경은 첫 페이지로 초기화하고 이전 요청의 응답을 새 조건에 표시하지 않는다.
- 데스크톱은 활동 추이·행동 비교를 나란히 표시하고 모바일은 카드와 펼침 목록을 가로 넘침 없이 이용한다.

### 상세 API

- `GET /api/admin/v1/user-analytics/activity/members`
  - `from`, `to`: KST 시작일과 종료일 포함, 최대 90일.
  - `eventName`: 선택값. 7개 서버 수집 이벤트 이름, 대소문자 무관. 미수집 이벤트 및 알 수 없는 값은 400.
  - `page=0`, `size=20`: 0부터 시작, 크기 1~100. 응답 `items`, `total`, `page`, `size`.
  - 회원 ID, 현재 닉네임, 선택 조건 이벤트 건수, 마지막 활동 시각. 최근 활동순, 동률은 회원 ID순.
  - 탈퇴·삭제 회원의 기록은 집계에서 누락하지 않고 닉네임만 null로 반환한다.
- `GET /api/admin/v1/user-analytics/activity/events`
  - 위 조건에 양수 `memberId` 추가. 회원별 이벤트를 발생 시각 내림차순, 동률은 이벤트 ID 내림차순 조회.
  - 이벤트 ID/이름, 발생 시각, 대상 종류/ID, 이전 중복 제거 기록 여부를 반환한다.
- 기존 어드민 인증 경계를 그대로 사용한다. 기존 overview 응답과 상위 100명 `report.members` 계약은 유지한다.
- 상세는 DB 집계·페이지 쿼리로 조회한다. 새 DDL이나 이벤트 수집 정책 변경은 없다.
- 지표와 상세는 독립 요청이므로 조회 사이 신규 기록이 발생하면 수치가 달라질 수 있다.
- 상단 기준일과 기간 필터를 분리하며 날짜 설정은 URL에 보존한다. 긴 집계 설명은 접힌 영역에 둔다.
