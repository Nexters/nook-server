# NOOK-414 어드민 콘텐츠 재수집

이슈: https://linear.app/nooknook/issue/NOOK-414

## 목적과 범위

실패 단계의 일반 재시도는 저장된 수집 응답을 재사용하므로, 내용이 부실한 캐시를 운영자가
명시적으로 버리고 Instagram 원문을 새로 수집할 수 있게 한다. 사용자 승인 후 구현했다.

- 기존 실패 재시도와 별도로 `POST /api/admin/v1/parsing-posts/{postId}/refetch-content`를 추가한다.
  요청은 필수 사유 `reason`(공백 제외, 최대 500자)이며 응답은 기존 게시물 복구 조회 형태다.
- 어드민 게시물 상세 → 처리 상태·실패 원인 화면에 **원문 새로 수집** 버튼을 추가한다.
  대상, 캐시 초기화와 장소 재처리 영향, 비용을 확인하고 사유를 입력한 후 예약한다.
- 완료·실패 콘텐츠만 허용한다. 본문·장소·후속 작업이 대기/진행 중이면 409로 거절한다.
  처리 불가 게시물과 수동 본문 수정 게시물, Instagram 외 소스도 거절한다.
- 해당 게시물 shortcode의 APIFY/BRIGHT_DATA Instagram 캐시만 삭제한다. 다른 게시물·사진 수집 캐시는 보존한다.
- 짧은 트랜잭션에서 캐시 삭제, 기존 콘텐츠 작업 PENDING 변경 및 감사 기록을 원자적으로 수행한다.
  외부 API는 이후 워커에서 호출한다. 실행 횟수와 과거 실패 이력은 유지하고 재시도 회차만 초기화한다.
- 새 수집이 성공하기 전에는 기존 콘텐츠·장소 단서를 유지한다. 성공하면 새 단서·OCR로
  장소 작업을 다시 예약한다. 기존 장소 작업 행과 실행 횟수를 유지해 오래된 시도의 쓰기를 차단한다.
- 이미 연결된 장소와 순서는 보존하고 새 장소만 뒤에 추가해 중복 키 오류를 방지한다.
  관리자 장소 교정과 사용자 저장 장소의 동결 정책은 기존 경로를 따른다.
- 재수집 중 일반 통합 재시도로 기존 장소 실패 작업을 먼저 실행할 수 없게 한다.

## 연계와 제외

자동 빈/손상 응답 차단·기존 불량 캐시 재수집은 NOOK-413의
[PR #255](https://github.com/Nexters/nook-server/pull/255)에 이미 구현돼 있다.
이번 main 기반 브랜치는 NOOK-414 변경만 포함하며 자동 복구를 중복 구현하지 않는다.
두 기능을 모두 사용하려면 NOOK-413과 NOOK-414를 함께 반영해야 한다.

정상 캐시는 일반 처리에서 계속 재사용한다. 강제 재수집은 유효한 콘텐츠라도 다시 외부 호출하며,
장소 0개인 정상 콘텐츠를 자동 실패로 취급하지 않는다.
원문 삭제·비공개·외부 서비스 장애의 복구 성공 자체를 보장하지 않는다.
이전에 연결된 장소 삭제, 기존 실패 후속 작업의 일괄 재시도, 운영 게시물 일괄 수정·실제 재수집,
DDL과 배포는 범위에 포함하지 않는다.

## 검증 기준

- 본문 완료·실패에서 재수집 예약, 실행 횟수와 기존 내용 보존, 중복 예약·진행 중 작업 차단.
- 처리 불가/수동 수정/누락 게시물의 캐시와 작업이 변경되지 않음, 실행자·사유 감사 기록.
- H2에서 대상의 양쪽 provider 캐시만 삭제 후 새 응답 저장 가능, 다른 게시물·소스 보존.
- 수집 성공 시 기존 장소 단서와 OCR 교체, 장소 작업 재예약, 실행 횟수 유지.
- 장소 재처리 시 기존 연결·정렬 보존과 새 장소 추가, 기존 일반 재시도·API 입력 검증 회귀.
- 단위·H2 테스트, Detekt, 모듈 의존 검사, 프론트 `pnpm build`.

MySQL 컨테이너 테스트는 임시 Gradle init script로 제외하며 저장소 설정은 변경하지 않는다.
Docker·브라우저·실제 provider 호출은 개인 검증 기준에 따라 실행하지 않는다.
화면의 실제 클릭·반응형 배치와 실서비스 재수집은 미검증이다.
추가 확인 시 게시물 상세 → 처리 상태·실패 원인 → 원문 새로 수집에서 사유와 영향 범위를 확인하고 예약한 후,
진행·결과 화면에서 본문 → 장소 작업 순서와 완료/실패 결과를 확인한다.

## 배포와 롤백

DB 스키마 변경은 없다. API·워커·어드민을 동일 버전으로 반영한다.
롤백 전 재수집으로 예약된 콘텐츠 작업이 끝났는지 확인한다. 이전 워커는 기존 장소 작업의
단서 갱신·재예약을 지원하지 않으므로 진행 중 재수집이 있다면 구버전 워커로 내리지 않는다.
기존 내용은 신규 수집 성공 시에만 기존 저장 정책으로 갱신되며 자동 데이터 복원은 제공하지 않는다.

## 최종 검증 결과 (2026-10-21 KST)

- 신규 회귀 테스트 9개 포함 단위·H2 테스트 902개 통과, 실패·오류·skip 0.
- Detekt, 모듈 의존 방향 검사, `git diff --check` 통과.
- `pnpm --dir nook-admin-web build` 통과. 번들 크기 경고는 남아 있다.
- MySQL 컨테이너 테스트 7개 클래스 제외: PlaceReprocessing, EmptyPlaceCompletion,
  ParsingExecution, ParsingSummary, PostProcessing, Onboarding, SavedPlaceSearch의 `MySqlTest`.
  따라서 컨테이너 검증까지 포함한 전체 check 통과로 표현하지 않는다.
- H2 신규 테스트의 감사 필드 설정 누락을 수정한 후 위 검증을 통과했다.

```bash
./gradlew check --continue --init-script /tmp/nook-414-unit-h2.gradle --max-workers=2 \
  -Dorg.gradle.jvmargs='-Xmx2g -XX:MaxMetaspaceSize=768m'
pnpm --dir nook-admin-web build
```

임시 init script는 테스트에서 `**/*MySqlTest*`만 제외한다. 실제 DB 변경·수집·배포·푸시는 하지 않았다.
develop 병합·푸시 및 main 대상 PR 등록은 변경과 검증 결과의 사용자 리뷰 후 진행한다.
