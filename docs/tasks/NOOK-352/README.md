# NOOK-352 후속 작업 재시도 추적과 복구 완료 표시

## 목적

실패 목록에서 재시도를 누르면 해당 항목이 사라지고, 성공 시 일반 완료로만 보이던 문제를 해결한다.
운영자가 요청한 작업이 대기·처리 중인지, 복구됐는지 또는 다시 실패했는지 확인할 수 있게 한다.

## 범위

- GET `/api/admin/v1/parsing-jobs/{jobId}` 단건 조회. 기존 관리자 인증과 오류 envelope 유지.
- 목록/단건/재시도 응답에 선택적으로 무시 가능한 `recoveryStatus` 필드 추가.
- 총 실행 횟수 > 현재 재시도 예산의 실행 횟수이면 수동 재시도 이력이 있는 작업이다.
  수동 재시도는 후자만 0으로 초기화하고 자동 재시도/선점은 둘을 함께 증가시키는 기존 불변식을 활용한다.
- NONE / RETRY_PENDING / RETRY_PROCESSING / RECOVERED / RETRY_FAILED로 구분한다.
- 재시도한 작업은 별도 카드에서 5초마다 단건 조회한다. 완료 또는 실패 시 자동 조회를 종료한다.
- 조회 오류는 마지막 확인 상태와 구분해 안내하고 재조회한다. 작업을 닫거나 다른 작업으로 바꾸면 기존 조회를 정리한다.
- 추적 작업 ID를 URL의 `recoveryJobId`에 보존해 새로고침/링크 공유 시 같은 작업을 조회한다.
- 기존 수동 재시도 완료 항목에도 복구 완료 배지를 표시하며 진행·결과 보기로 추적할 수 있다.

## 제외 범위

DDL, 전체 재분석, 상세 실행 로그/진행률, 과거 실패 사유 복원, 자동 재시도의 복구 배지,
현재 작업 여러 건을 동시에 고정해 추적하는 기능은 포함하지 않는다.

## 검증

- 실제 MySQL에서 수동 재시도 대기/처리/재실패/재복구 조회, 일반 자동 재시도 성공 구분 및 없는 작업 조회.
- API 단건 ID 검증, 없는 작업 오류, 복구 상태 DTO 전달.
- 내장 브라우저와 로컬 모의 API: FAILED 필터에서 별도 추적 유지, 자동 복구 완료 전환,
  기존 복구 배지, 새로고침 후 작업 유지, 단건 조회 오류 안내.
- `./gradlew check --no-parallel --max-workers=2 -Dorg.gradle.jvmargs=-Xmx2g` 통과.
- `pnpm --dir nook-admin-web build` 통과.

## 배포

스키마 변경 없음. 기존 API 필드는 유지한다. 새 API 배포 후 단건 추적과 복구 배지를 확인한다.
본 작업은 NOOK-348의 후속 변경이며 dev 우선 검증한다. live 배포는 별도다.
