# NOOK-245 장소별 근거 기반 100개 태그 카탈로그 적용

## 목적

모든 장소에 `아늑한`, `모임`, `감성적인`, `데이트`가 반복되는 문제를 줄이고, Instagram 게시물에서
해당 장소를 설명하는 명시적 근거가 있을 때만 합의된 태그를 노출한다.

## 범위

- 분위기, 공간, 목적, 경험, F&B 각 20개로 구성된 100개 태그 카탈로그를 정의한다.
- 본문과 해시태그의 매칭 키워드로 후보를 만든 뒤 AI가 후보 안에서만 선택한다.
- 다중 장소 게시물에서는 장소별 본문 구간을 분리한 뒤 모든 장소를 하나의 AI 요청으로 처리한다.
- 다중 장소 게시물의 공용 해시태그는 개별 장소 근거로 사용하지 않는다.
- 장소명, 주소, 업종은 태그 후보 근거로 사용하지 않는다.
- confidence 0.65 이상, 장소당 최대 4개, 같은 분류 최대 2개만 저장한다.
- 근거 키워드가 없으면 AI를 호출하지 않고 빈 태그 목록을 저장한다.
- 근거 후보가 있더라도 AI 호출은 Instagram 게시물당 최대 한 번만 수행한다.
- 장소 대표 태그 캐시에도 같은 분류 제한을 적용한다.
- 조건부 batch runner로 기존 게시물·장소 연결의 태그만 다시 생성할 수 있게 한다.
- 100개 카탈로그를 `place_tag_catalogs`에 저장하고 관리자 화면에서 노출명, 분류, 매칭 키워드,
  활성 여부와 정렬 순서를 수정할 수 있게 한다.
- 카탈로그 변경은 운영자와 사유를 포함한 감사 로그로 남긴다.
- 비활성 태그는 이후 추론 후보와 사용자 API 응답에서 제외한다.

## 태그 카탈로그

- 분위기: 감성적인, 아늑한, 조용한, 차분한, 따뜻한, 정갈한, 깔끔한, 세련된, 힙한, 빈티지한,
  레트로한, 이국적인, 고급스러운, 캐주얼한, 로맨틱한, 활기찬, 편안한, 독특한, 자연스러운, 몽환적인
- 공간: 아담한, 넓은, 쾌적한, 개방적인, 프라이빗한, 채광 좋은, 뷰 좋은, 통창, 창가, 테라스,
  루프탑, 야외, 정원, 한옥, 오션뷰, 리버뷰, 시티뷰, 숲뷰, 인테리어, 포토존
- 목적: 데이트, 모임, 소개팅, 혼자, 혼밥, 혼카페, 작업, 공부, 대화하기 좋은, 독서, 기념일, 생일,
  가족모임, 회식, 친구모임, 반려동물, 아이와, 나들이, 여행, 드라이브
- 경험: 숨은명소, 핫플, 신상, 로컬, 웨이팅, 예약필수, 예약가능, 가성비, 특별한, 사진찍기 좋은,
  재방문, 오래된, 노포, 유명한, 친절한, 여유로운, 북적이는, 접근성 좋은, 주차가능, 심야
- F&B: 브런치, 베이커리, 디저트, 커피, 케이크, 와인, 칵테일, 위스키, 전통주, 비건, 채식,
  파인다이닝, 코스요리, 오마카세, 다이닝바, 펍, 티룸, 맛집, 술집, 카페

초기 매칭 키워드는 `PlaceTag.defaultDefinitions`와 DDL seed를 동일하게 유지한다. 런타임의 단일 진실
공급원은 `place_tag_catalogs`이며, enum의 변경 불가 코드는 기존 저장값과의 호환을 위해 유지한다.
`GENEROUS(푸짐한)`와 `FAST(빠른)`는 과거 DB 값 역직렬화를 위해 enum에 남기되 카탈로그에는 넣지 않는다.

노출명과 활성 여부는 조회 응답에 즉시 반영된다. 분류와 키워드 변경은 이후 파싱부터 적용되며, 기존
저장 태그까지 다시 계산하려면 아래 backfill을 명시적으로 실행한다. 태그 코드는 생성·수정·삭제하지 않는다.

## 제외 범위

- 사용자 자유 태그 입력과 편집
- 관리자 화면에서 태그 코드 생성·수정·삭제
- 외부 지도 리뷰 기반 태그 생성
- 태그 API 응답 필드 또는 타입 변경
- 근거가 없는 태그 강제 생성

## 기존 데이터 재생성

애플리케이션 배포 전에 `ddl/up.sql`을 적용해 카탈로그 테이블과 100개 초기값을 생성한다. 애플리케이션
배포 후 기존 태그를 새 정책으로 다시 계산하려면 batch 애플리케이션을 다음 환경변수와 함께 한 번 실행한다.

```shell
PLACE_TAG_BACKFILL_ENABLED=true ./gradlew :nook-api-batch:bootRun --args='--spring.profiles.active=dev'
```

실패한 게시물만 재시도하려면 쉼표로 구분한 원본 게시물 ID를 함께 지정한다.

```shell
PLACE_TAG_BACKFILL_ENABLED=true PLACE_TAG_BACKFILL_POST_IDS=197,277 ./gradlew :nook-api-batch:bootRun --args='--spring.profiles.active=dev'
```

backfill은 활성 원본·사용자 저장 게시물과 연결된 장소를 원본 게시물별로 묶어 조회하고, 게시물당 최대
한 번의 AI 요청으로 장소별 태그를 멱등 교체한다. 실패한 게시물이 1개 이상이면 batch를 실패 처리하며,
같은 명령을 다시 실행할 수 있다.

## 성공 기준

- 선택 가능한 태그가 정확히 100개이고 각 분류가 20개다.
- 후보 밖의 태그와 confidence 0.65 미만 태그는 저장되지 않는다.
- 장소당 최대 4개, 같은 분류 최대 2개가 보장된다.
- 다중 장소 게시물의 장소별 입력 본문이 분리되고 AI는 게시물당 최대 한 번 호출된다.
- 근거 키워드가 없으면 빈 태그 목록을 저장한다.
- 기존 `tags: List<String>` API 계약을 유지한다.
- 관리자 API와 화면에서 100개 태그를 조회하고 변경 사유와 함께 수정할 수 있다.
- 비활성 태그는 새 AI 요청의 후보와 사용자 응답에 포함되지 않는다.
