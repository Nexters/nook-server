# NOOK-272 Google 장소 사진 상세주소 정규화

## 목적

Google Maps 장소 사진 후보 주소에 층과 호수 같은 상세주소가 포함되어도 저장 장소와 같은
건물인지 정확히 판정한다.

## 원인

기존 도로명 주소 키는 주소의 마지막 두 토큰을 사용했다. 저장 주소가
`서울 중구 을지로 130-1`이고 Google 주소가
`대한민국 서울특별시 중구 을지로 130-1 4층 401호`이면 후자는 `4층 401호`를 주소 키로
사용해 같은 건물임에도 매칭에서 제외됐다.

## 범위

- 주소에서 도로명과 건물번호를 찾아 비교
- 층과 호수 등 뒤따르는 상세주소 제외
- 실제 `아사시`와 `ASASI` 주소 형태를 사용한 회귀 테스트 추가

## 제외 범위

- 한글명과 영문명 사이의 유사도 기반 매칭
- 릴스 영상 포스터를 장소 사진으로 사용하는 fallback
- 장소 썸네일 provider chain 변경
- 공개 API와 데이터베이스 스키마 변경
- 클라이언트 변경

## 성공 기준

- `서울 중구 을지로 130-1`과
  `대한민국 서울특별시 중구 을지로 130-1 4층 401호`를 같은 도로명 주소로 판정한다.
- 기존 이름, 주소, 거리 및 카테고리 후보 필터 정책을 유지한다.
- `./gradlew check`가 성공한다.

## 검증

- `./gradlew :nook-api-infrastructure:test --tests '*ApifyGoogleMapsPhotoProviderTest'`
- `./gradlew detekt`
- `./gradlew check`

## 배포 및 롤백

스키마와 공개 API 변경은 없다. 애플리케이션만 배포하며 문제가 생기면 이전 버전으로 롤백한다.
