# NOOK-389 장소 병합 중복 저장 및 처리 실패 알림 재발송 방지

## 목적

서로 다른 provider 장소 후보가 동일한 내부 장소로 병합되더라도 게시물에는 한 번만 연결한다.
처리 실패가 그대로인 동안 성공한 후속 작업만 추가되는 경우에는 같은 실패 알림을 다시 발송하지 않는다.

## 범위와 성공 기준

- provider 후보를 장소 identity로 해석한 뒤 내부 `placeId` 기준으로 중복을 제거한다.
- 최초로 확인된 후보의 순서와 미디어 출처를 대표 연결 정보로 유지한다.
- 실패 요약 fingerprint에는 실패 작업과 장소 없음 경고의 실질적인 상태만 반영한다.
- 실패 사유, 단계, 시도 횟수 또는 실패 시각이 바뀐 실제 재시도 결과는 새 알림 대상이다.
- 성공 후속 작업의 추가만으로는 기존 실패 알림을 다시 발행하지 않는다.

## 제외 범위

- live 데이터 직접 수정 및 기존 실패 작업 재실행
- API 계약 또는 DB 스키마 변경
- 장소 identity 병합 정책 자체의 변경

## 검증

- 서로 다른 후보가 동일한 `placeId`로 병합되는 장소 저장 회귀 테스트
- 동일 실패 이후 성공 후속 작업이 추가되는 요약 발행 회귀 테스트
- 실제 실패 재시도와 장소 없음 경고의 기존 재발행 계약 유지
- 관련 단위 테스트 21건 성공
- domain, application, presentation, worker, batch 모듈 테스트 성공
- `./gradlew detekt` 성공
- 로컬에 Docker 실행 환경이 없어 MySQL Testcontainers 통합 테스트와 전체 `check`는 실행하지 못했다.
  dev VM Docker 소켓 연결도 임의 컨테이너 포트가 외부에 노출되지 않아 준비 확인을 완료하지 못했다.
